# Story frame count

用户先决定想读多详细，再由模型依据已读取的故事推荐画幅数。用户可保留建议或调整数量，之后才生成完整分镜与图片。详略不是固定数量档位，短故事不为凑数拉长。

## Acceptance（本轮 !! 修订，替代原自动/指定入口）

- [x] 新故事先提供“简短 / 适中 / 详细”，默认适中；三者分别控制事件压缩、完整叙述、细节与停顿，不绑定固定幅数或强制 30–60 幅。
- [x] Gemini 和 Codex 都基于已核对并保存的原文、详略与制作要求，返回 1–60 的整数建议及一句不剧透的理由；原文无法取得或输出无效时明确失败，可恢复，不先生成完整分镜或图片。
- [x] 建议在当前生成面板展示；同步滑块和数字输入支持 1–60，1 幅显示“单幅概述”，可恢复推荐数量。用户点击生成后按选定数量严格生成分镜；生成中锁定，不能在确认前通过其他请求提前生成。
- [x] 建议、原文及确认状态持久保存；刷新、书架继续、网络重试和并发确认不会重复推荐、改变已确认数量或重生成已完成结果。失败可重试，待调整阶段不被误标为完成或一直轮询。
- [x] 旧 numeric/auto 故事保持可读可恢复，既有分镜不重排；保留 1–60 读页/进度/媒体、首图与后三幅批次；无需数据库迁移。
- [x] 更新说明并完成两种 provider 的受控 REST/真实 SQLite 回归和可见 UI 验证，区分受控推理与真实模型质量。

## Boundaries

本轮明确加入生成前的数量选择，替代此前“不增加生成前审批”的边界；不增加逐幅分镜审批。原文与推荐组成一个可恢复检查点，确认后保留既有编排/绘图流程。旧客户端缺少详略字段时仍走旧路径；新 UI 一律使用新流程。推荐阶段占用既有新故事日额度，恢复不重复计数。不调用真实付费生成，不改超时/锁租期，不构建 Docker 或桌面安装包，不推送。保留其他桌面、图标改动。
