# 全书索引与书—主题—故事缓存

目前每次选主题都会重新通读全书，换一批也重复读取正文。用户选择：先建立可复用的全书故事索引，再按主题筛选；要求书—主题—故事缓存。此前真实页面已确认《警世通言》从 0% 更新至 39%（146,243 / 373,619 字），但开发自动刷新打断了完整验证，不能声称已经跑完。

- [ ] 首次选题分批通读全部本地正文，建立与当前主题无关的、来源可核对的故事索引；先合并索引，再按主题选至多五个故事。索引保存可独立改编的故事候选，不宣称穷举所有可能的改编切法。
- [ ] 持久保存完成的索引批次和合并后的全书索引；后续主题选择、换批、进程重启复用索引，不重新发送原文。
- [ ] 按书籍版本、主题缓存已核对故事；重复请求直接返回缓存，排除已看标题与重复出处；缓存不足时仅从全书索引补选，候选耗尽明确告知，不偷偷重读正文。
- [ ] 原文版本、解析后正文、索引规则或所配提供方/文本模型改变时索引自动隔离，选题规则改变时仅主题结果隔离；读到损坏或失效出处不返回旧缓存。
- [ ] 同进程并发相同索引或主题任务合并，单个用户取消不影响其他等待者；无人等待则停止派发后续批次，已完成结果仍保存。
- [ ] 字数进度覆盖索引构建，保留 Unicode 字符计数、重叠去重；最终选题阶段与缓存命中明确显示。旧 JSON 接口、来源核对和分镜流程保持可用。
- [ ] 有自动化证据证明冷启动、热缓存、换主题、换批、重启、并发、取消、版本失效和异常路径；实际用《警世通言》确认进度更新，并验证再次选题命中缓存。

边界：使用现有运行数据目录和原子 JSON 存储，不引入向量数据库、检索服务、跨进程分布式锁或新的云服务；不构建 Docker，不推送 Git，不改原文资料。首次索引仍有模型成本，后续按主题只发送简短索引。开发环境的后台文件改动可能导致页面重载，验证须避免依赖易被刷新的长页面请求。
