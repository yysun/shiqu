# CLI 共享书库与单一桌面版

CLI 成为已有 Node 用户的入口；桌面版只保留内置 Node 的版本，避免 Lite 重复分发。CLI 先找到或创建桌面已保存的书库，找不到时再询问用户，不能静默打开一个新空书架。

## 验收

- [x] CLI 目录优先级为显式参数/环境 > 桌面已保存目录 > CLI 已确认目录 > 已存在的桌面默认书库；其余情况交互询问，默认建议桌面兼容目录。已保存目录不存在则自动创建，不再询问。
- [x] 非交互首次启动未指定目录时明确失败并提示 --data-dir；取消不创建书库。桌面设置损坏时明确失败，不泄露密钥或静默切换。只读桌面设置，不读取凭据或覆盖桌面配置。
- [x] 确认的 CLI 目录可跨启动复用；原 CLI 独立书库保留，不自动搬移/合并，文档说明如何显式使用。默认平台路径与桌面一致。
- [x] CLI 与桌面互斥使用同一书库；正常退出、启动失败后释放占用；真实 SQLite 和媒体/阅读记录可在两入口间复用。
- [x] 删除 Lite 配置、脚本、系统 Node UI/运行时和 CI 发布分支，只保留内置 Node 的桌面发行；旧设置中的 nodePath 字段继续可读但不能覆盖内置 Node。
- [x] README、使用指南、开发/桌面/npm 说明反映 CLI 和单一桌面入口、目录查找/询问、凭据独立及手机访问差异，保留用户已有截图改动。
- [x] 相关单测、完整 JS 套件、类型检查、lint、适用的 Rust 检查和本地进程验证通过；不构建或打包 Docker/桌面，不发布。

范围：不改 AI、故事格式、迁移 SQL；不自动复制数据、密钥，不删除历史 Release 或历史 story 文档。
