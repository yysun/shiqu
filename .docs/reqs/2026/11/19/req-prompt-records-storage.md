# 提示词记录移出故事文档

## 问题

每次模型调用都把完整提示词（系统指令、输入、输出契约、参考图）作为 `usage[].promptRecord` 写进故事的 `document`。在实际书库中它占全部故事文档的 82%（4350 万字符中的 3590 万字符），而且同一故事家族的修订会复制父版本的全部记录（2822 条记录中只有 1623 条不同）。

只有“提示词”查看与导出、审校历史两处需要这些记录；其余每次读取、解析和写入故事（制作节拍、打开故事、每次 `json_set` 保存、WAL、备份）都在搬运它们。

## 目标

故事文档不再内嵌提示词全文；提示词按内容只存一份，需要时按引用读取。用户看到的提示词、审校历史和导出内容不变。

## 验收标准

- [ ] 新的模型调用保存后，故事文档中的调用记录只含提示词引用，不含提示词全文；全文可通过引用读取。
- [ ] 内容相同的提示词只存一份；修订和复制的故事沿用父版本的引用，不复制全文。
- [ ] 升级把书库中已有的内嵌提示词全部移出并建立引用；迁移结束前核对每个引用都能读到与原文相同的记录，否则整次迁移回滚。
- [ ] “提示词”接口、审校历史接口和故事导出（含 `提示词.json`）的内容与迁移前一致（记录、顺序、缺失项、来源故事和序号相同）。
- [ ] 仍内嵌提示词的文档（例如旧版应用写入）照常显示和导出。
- [ ] 在实际书库副本上，故事文档总字符数和单篇平均大小下降约 80%；提示词存储因去重减少约 40%。
- [ ] 升级沿用已验证的整库备份和迁移流程；`latestMigration` 更新；`schemaVersion` 不变。
- [ ] 读者 API 的其他响应、会话类型字段、公开导出格式不变。

## 约束

- 测试使用隔离数据，不触碰用户书库。
- 迁移失败时书库保持迁移前状态（事务回滚，备份可用）。

## 兼容说明

- 迁移后，支持当前格式的旧版应用仍可打开和写入书库，但它们的“提示词”页面会把已移出的记录显示为缺失；旧版应用新写入的内嵌记录在新版中照常可读。不因此提升 `schemaVersion`。

## 非目标

- `production_jobs.result` 中随任务结果保存的提示词（约 700 万字符）。
- 删除不再被引用的提示词记录、压缩数据库文件（`VACUUM`）。
