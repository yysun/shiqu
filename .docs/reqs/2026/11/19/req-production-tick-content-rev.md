# 制作调度节拍只读取有变化的故事

## 问题

制作协调器每秒执行一次调度节拍。其中两项故事检查每次都把整行故事（`document`、`selection`）从 SQLite 复制到 JavaScript：

- 检查已暂停或停止、但可能已完整的故事是否应标记为完成：在实际书库中每秒读取 30 篇、约 907 万字符，并对每篇解析 JSON 两次。这些故事尚未完成，结果每秒重复相同。
- 清理过期任务：每秒读取 21 篇有排队或失败任务的故事、约 280 万字符，只为与上一节拍比较文本。

合计约每秒 1190 万字符的复制、解析和回收，且随暂停故事增多而增长。该节拍本身不调用模型，开销纯属本机 CPU、内存和垃圾回收。

## 目标

故事内容和任务计数未变时，节拍不再读取或解析故事全文；故事有任何改动（无论由哪段代码写入），下一个节拍仍能发现并按原规则处理。

## 验收标准

- [x] 书库为每篇故事保存一个内容修订号。`document` 或 `selection` 任何写入都会使其变化，包括不更新 `updated_at` 的局部 JSON 写入。
- [x] 完成检查和过期任务清理在故事内容及相关任务计数未变时，不读取该故事的 `document` 或 `selection`。
- [x] 完成检查、过期任务清理及按需求重建任务图三处，每个节拍读取故事全文的数量只与上次检查后有变化的故事数相关，与暂停或停止的故事总数无关。
- [x] 判断哪些故事有变化的轻量查询无需读取故事行本身（由索引直接回答）。
- [x] 已暂停的故事在任意写入后变得完整时，下一个节拍仍会将其标记为完成；未变化的不完整故事不再重复解析。
- [x] 应用重启后，首次节拍对所有候选故事完整检查一次，保持崩溃恢复行为。
- [x] 过期任务清理在故事内容或排队、失败任务数变化时仍按原规则执行，强制清理指定故事时仍会执行。
- [x] 完成检查重用已解析的故事，不再对同一行重复解析。
- [x] 升级沿用已验证的整库备份和迁移流程；`latestMigration` 更新为新迁移；支持当前格式的旧版应用仍可打开升级后的书库。
- [x] 读者 API、会话类型和字段、`stories` 表的列、导出内容不变；故事写入不因记录修订号而重写整行。

## 约束

- 迁移是普通 `drizzle/` 迁移，经 `ensureLibraryReady()` 在备份后应用；不提升 `schemaVersion`。
- 不改变制作队列、租约、需求过期及模型调用的规则。
- 测试使用隔离数据，不触碰用户书库。

## 非目标

- 将提示词记录移出 `document`（单独改进）。
- 改为事件驱动的完成检查，或调整节拍频率。
- 优化其他按需读取整篇故事的路径（打开故事、导出、制作任务本身）。
