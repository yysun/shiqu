# 重做故事卡向量检索

用户可能想浏览指定章节、找回记得标题或情节的一则故事，或按主题找多则故事。现在的向量检索依赖预制查询词，用户换一种说法就可能只走字词匹配。用户应能选自己的 Embedding 模型，用它建立本地索引，并用同一模型实时向量化查询。

## 设置与建库

- [x] 「我的 → 嵌入模型」可选择用户已有的本地 Embedding 服务和模型，测试连接、保存、开启或关闭向量检索。页面分别显示模型是否可用、索引是否就绪和已覆盖的书籍。嵌入设置与生成和原文核对模型独立。首版接入本地 Ollama，不随应用下载或打包模型。
- [x] 每个用户书库只有一个故事卡向量库，保存在用户故事目录并随书库备份恢复。库内按书和原文版次区分。一张故事卡只用标题和白话梗概生成一条向量，并能回到该卡对应的原文范围。内置或自建且有可核对出处的故事卡都可入库。「故事」和「主题」共用此库，查询向量按需生成。
- [x] 用户可以选书建库，看到进度和失败原因，取消后可重试。重复建库不产生重复记录。书籍版次或卡片内容改变时，受影响的旧向量停止参与召回，可单独更新该书。没有故事卡的书明确显示未覆盖，仍能从目录浏览和通过原文查找。
- [x] 查询只使用与建库时模型标识、版本、维度和编码规则兼容的向量。同维度的不同模型也不能混用。切换模型后提示重建，新库就绪前继续提供非向量检索。建库中断或备份恢复后，未完成或不兼容的数据不会被当作可用索引。
- [x] 停用旧的预制查询向量和官方向量包。即使旧索引仍在磁盘上、查询恰好命中旧词条，检索也只使用新库中的故事卡向量和实时生成的查询向量。用户导入的旧文件保留，出处仍有效的故事卡可用来重建，旧向量不迁入新库。

## 章节、故事、主题

- [x] 同一个选书页提供「章节」「故事」「主题」三个入口。系统按入口采用相应的检索方式，用户只需选择想找什么。
- [x] 「章节」可浏览目录或按卷名、篇名搜索，选中后直接看原文和已有故事卡。目录、原文和已有故事卡在未配置模型时也可查看。用户要从所选章节提取更多故事时，可调用文本模型读取原文。
- [x] 「故事」用于定位某一则故事。标题或已有别名精确匹配时优先显示，唯一命中可直接打开出处，无需等待模型。其他输入先搜故事卡标题、别名和梗概。只记得情节、文字匹配无法定位时，有兼容索引就实时嵌入查询，补充语义候选。结果显示标题和原文出处，供用户确认是哪一则。
- [x] 「主题」用于查找多则符合条件的故事，默认搜全书，可用章节缩小范围。向量库已开启且当前范围有兼容索引时，对实际输入实时做 Embedding，将向量召回与故事卡、原文字词召回合并，按出处去重，最多取 50 条交给文本模型核对原文并排序。正式匹配结果显示出处和匹配依据，且不越出所选范围。
- [x] 未开启、未建库、索引不兼容或嵌入调用失败时，「故事」和「主题」仍可用故事卡、原文字词和有效缓存找候选。「主题」有核对模型时按原文确认，否则可浏览明确标为未核对的候选及出处。
- [x] 「故事」未能定位到所找故事，或「主题」没有核对出匹配、用户想找更多时，可发起「继续查找原文」。文本模型复用已提取的故事和已读进度，按范围分批读取原文，提取并核对故事是否符合查询。用户能看到进度并取消。缺少可用文本模型时明确说明原因。界面区分「候选中没找到」与「已检查完整个所选范围」。索引仅覆盖部分章节时，也显示覆盖范围。

## 交互设计

- [x] 先做桌面与手机的可点击原型，用现有选书流程验证三个入口。每个入口用一句话或一个示例让用户看懂能做什么，例如「浏览卷十一」「找《种梨》」「找求雨的故事」。用户选定入口后，当前页面只呈现完成这项任务所需的输入和操作。
- [x] 书名和当前检索范围随时可见。主题默认搜全书，选章节是一项可跳过的筛选。打开原文再返回时，保留当前书、入口、查询、范围和结果。
- [x] 找故事和主题结果使用相同的卡片结构，优先展示故事名、简短梗概和可打开的出处。主题结果清楚显示核对进度和匹配理由。没有结果时，说清查过的范围并给一个明确的下一步，例如「继续查找原文」。
- [x] 搜索页使用用户能理解的状态，例如「正在核对原文」。嵌入模型和建库配置集中在「我的」，未配置或服务异常时仍可直接搜索。需要用户处理时，从状态提示可直接进入相应设置。

## 验收与范围

- [x] 实现前在手机与桌面原型走通三项首次使用任务。用户无需额外说明即可选对入口、完成一次查询或目录浏览、打开原文并返回。另走通未配置模型、候选未命中和分批查原文三种状态，检查用户是否能判断查到哪一步、接下来能做什么。
- [x] 验证未配置模型时能按卷名进入章节，以及「故事」能用《种梨》精确定位，或用「那个道士当街种梨的故事」召回正确故事。验证两个入口都能打开正确的原文出处。
- [x] 用同一批有已知出处的主题查询比较「故事卡文字检索」和「故事卡实时向量＋文字检索」。至少覆盖《搜神记》同卷多则故事、未预制的白话改写（如「求下雨」）、指定章节和无匹配主题。记录正确故事进入前 50 的情况、最终原文核对结果和耗时，并验证查询确实调用所选模型。针对无索引、模型不兼容及模型服务失败分别验证退路。

首版只为故事卡存向量，沿用已发布的内置故事卡，停止制备和分发旧式向量包。现有 CLI 查书和导入入口如需调整，须同步使用说明与内置技能。旧文件中故事卡的复用方式和建库调度留到方案阶段决定。

## 约束

- Embedding 服务首版只接入用户已安装并运行的本地 Ollama；不下载模型，不复用生成或原文核对的模型设置。
- 所有向量数据按用户书库隔离，备份与恢复必须保留可用状态；旧索引文件不迁移、不删除。
- 原文和出处仍以当前本地书库为准，向量只能召回候选，不能替代原文核验。
- 继续支持未配置 Embedding、Ollama 不可用及索引不兼容时的目录、文字检索和原文查找。

## 非目标

- 不接入云端 Embedding 服务，不自动安装或下载 Ollama 模型。
- 不为整段原文、事件、片段或查询词预制向量；不保留旧官方向量包作为检索回退。
- 不改变生成、审片、书库所有权及原典内容的存储格式。
- 不在本次制作桌面安装包或发布应用。
