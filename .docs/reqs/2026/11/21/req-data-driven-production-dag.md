# 需求：数据驱动的制作 DAG

## 问题

[故事制作与编辑 DAG](../../../../story-production-dag.md) 已定为新的制作规范，现有实现与它不一致：

- 下一步由手写的 `nextStep()` 推导，修订影响由 `revisionImpact()`、`reusableRevisionImages()` 等逐条规则判断，规则分散在多处，难以与规范逐条对齐。
- 绘图读取配文、制作要求和全部人物设定，导致小改动重绘过多；审片只有整篇结论，一处修改会重审全篇。
- 修订提交后立即恢复制作，没有「已保存，等待继续」；故障、手改、模型设置和升级都缺少规范要求的行为。

## 目标

制作与编辑行为符合 DAG 规范。规范中的节点目录与调用契约以声明式配置表达，由一个通用引擎统一计算产物有效性、就绪、重做预估和任务身份；新增或修改节点只需改配置。

## 验收标准

### 配置与引擎

- [ ] 规范「节点目录」的每个节点和「调用契约」的每个调用，在配置中各有且只有一项；自动检查在配置与规范表格不一致时失败。
- [ ] 产物有效性、就绪判断、保存前的重做范围预估和任务身份，都由同一个引擎依据配置与已保存产物计算；修订与调度代码中不再保留针对单个节点的失效规则。
- [ ] 规范「实现后的验收场景」中不需要真实模型的场景，都有使用替身生成器的自动测试，测试按场景编号可追溯；需要真实模型的场景列为手动模型验证。

### 产物模型

- [ ] 画幅有稳定身份，插入、删除、重排、合并、拆分按规范保留或分配身份。
- [ ] 人物设定按人物分条，带名字与别名；每幅保存候选人物与入画人物，并按规范的来源更新。
- [ ] 验收要求按条目保存，每条有稳定身份和可修改的范围与依据登记。
- [ ] 每个产物记录内容指纹、硬输入指纹、来源、手改标记和旧规则标记；显示名、署名、收藏和阅读位置不进入任何指纹。

### 调用

- [ ] 每次模型调用读取的内容不超出调用契约：叙事分镜不含画风，画面描述与叙事分镜分开生成，人物设定与提纲互不读取，绘图与横图只读取各自列出的输入。
- [ ] 逐幅与逐条的调用按批执行：一次调用只包含本轮需要生成的实例；首次制作 24 幅时叙事分镜与画面描述各两次调用，只有一幅画面描述失效时只为该幅调用一次；同批其他实例不影响本幅的有效性。
- [ ] 审片按两个阶段执行，每个阶段有失效结论时最多调用一次；调用只替换允许清单内的结论，清单外的判断记为建议。

### 审片与修订

- [ ] 审片产出逐幅结论、全篇叙事结论和逐条全篇验收结论，各自绑定自己的输入；编辑只使受影响的结论失效。
- [ ] 放行只更新被放行的结论；可绘图状态由全部结论推导。
- [ ] 读者确认的标题与结语不被审片改选。
- [ ] 自动修订不覆盖、不删除、不合并含手改的画幅，遇到时停在「需读者处理」。
- [ ] 每个保存的修订有 20 次自动修订额度，「继续自动修复」授予新的 20 次。

### 保存与继续

- [ ] 制作确认后保存影响制作的修改，进入「已保存，等待继续」；点击「继续制作」前新版模型调用数为零；保存后没有需要重做的节点时保持原制作状态。
- [ ] 「应用修改并恢复」「保存并重新审核」和确认后修订的「开始制作」改为「保存修改」加「继续制作」；桌面界面、CLI 与 `skills/shiqu/SKILL.md` 语义一致。
- [ ] 保存前显示接续点、将失效的图片数和「使用旧参考」的画幅数。

### 故障与模型

- [ ] 普通修订按规范延续或放弃上一版故障，包括「待匹配」；延续故障需要针对新版的恢复动作。
- [ ] 故障只阻断依赖它的工作；会话可从 `failed` 由不依赖故障的普通任务进入 `running`；可选产物的故障不阻断完成与导出。
- [ ] 「内容被拦截」不自动重试；服务级故障不写入各篇步骤故障；调用超时按中断处理。
- [ ] 制作确认记录模型快照与绘图参数；全局设置变化只影响新故事；「应用当前模型设置」只影响之后的调用。

### 升级

- [ ] 已有故事在下一个检查点转换为新模型，不调用模型；转换原子、可重复，中断后重做结果相同。
- [ ] 转换得到的记录标为旧规则，按规范支持阅读、接续与完成判定，输入变化后按新规则失效。
- [ ] 升级前完成经核对的整库备份；新迁移更新 `db/library-format.json` 的 `latestMigration`。
- [ ] 升级后的书库被不支持新格式的旧版应用拒绝打开；回滚方式为升级前备份加对应旧版应用。
- [ ] 升级时已付费待发布的图片结果被发布而不重新绘制；其余旧任务、未结故障与回执有确定的映射或作废规则。

### 文档

- [ ] [故事生成状态机](../../../../story-generation-state-machine.md)与[用户指南](../../../../user-guide.md)中的步骤推导、按钮和恢复说明与新行为一致。

## 约束

- 改进必须进入正式制作流程；测试与评估工具调用同一实现，使用隔离数据。
- 保持阅读 API 路径、Session 类型与模块、`session_id` 列稳定；`stories` 继续保存故事与修订，`production_jobs` 继续保存执行任务。
- 访问书库前经 `ensureLibraryReady()`；迁移测试和破坏性探查不得作用于用户书库。
- 导出 ZIP 的公开结构与图片字节规则不变。
- 遵守桌面界面约定：制作步骤用 `ProductionTimelineRow`，次要操作用 `StoryFlowAction`；新增代码注释使用中文。

## 非目标

- 图片内容的自动审核。
- 引入外部工作流框架、独立服务或第二套制作管线。
- 新增模型服务商，或改变导出格式。
- 规范之外的性能优化与界面改版。
