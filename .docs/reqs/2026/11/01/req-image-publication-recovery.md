# 图片保存冲突后的恢复

现场：第二版《雪日探钗，黛玉含酸》有 30 幅、已保存 16 幅，队列同时保留两个 image version。当前版本第 9、10 幅 image-publish 因 document 已保存另一 URL 失败，界面显示“重试展开”，重新排队仍然遇到相同冲突。

- [ ] 过期图片任务不能继续调用绘图、写入当前故事，或阻塞当前制作状态。
- [ ] 显式重试能恢复已保存图片与当前 publication 结果冲突的记录，不反复报“图片已经更新”。恢复已有图片的步骤不得调用绘图模型。
- [ ] 保留其他已保存图片和历史故事；当前版本真正缺失的图片仍需显式同意重绘。
- [ ] 阅读界面统一显示“重试生成”；说明区可解释图片已生成、只重试保存。
- [ ] 测试覆盖两个 version 共存、旧任务晚到、已有失败记录重试、付费调用次数及手动暂停/停止边界。

非目标：不修改生产数据库、不发起真实模型调用、不构建 Docker 或桌面包。工作区另有选题实现改动，不纳入本次提交。
