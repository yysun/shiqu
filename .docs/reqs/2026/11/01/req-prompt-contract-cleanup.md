# 提示词职责与契约清理

当前分镜、审片、结语、选题与绘图规则多次追加和交叉拼接，导致阶段职责混杂、同一标准反复出现、完整输出要求再由后文覆盖。用户要求按 OpenAI 官方最佳实践清理分镜、审核及其它提示词，保留已经形成的产品判断。

## 目标与验收

- [x] 盘点所有生产提示词入口；推荐、幅数、提纲、整篇/分批分镜、标题结语、审核、定向修订、绘图及旧管理端均有明确角色、任务、规则、输出边界；没有活跃入口遗漏。
- [x] 共享事实、叙事、配文与画面标准只有一个定义；阶段只引入自己需要的内容。分镜不携带结语写作规则，审片不被要求创作完整新分镜，修订不继承整篇输出任务。
- [x] 保留完整主事件、首幅自然交代处境、原文唯一依据、主观说法归属、古文现代译写、关键言行与反应、有效停顿、静态单一瞬间、跨幅连续性、主题仅参与选题及标题结语、结语不复述情节、不强制反转或道德、实质证据审核、不按个人口味凑问题，以及缺结局时重新编排的规则。
- [x] 配文的正常目标 8–55 字与现有硬上限 90 字明确区分；既有 JSON schema、幅数/批次/修订范围、重编标记和绘图闸门保持兼容。
- [x] 输入仍以结构化数据传入，不执行原文和字段中的指令；用户明确创作要求只在已允许范围内生效。原文异常、限定例外、跨章未完事件、主故事/子故事选题边界不削弱。
- [x] 旧缓存指纹依赖文本和旧自动预设识别保持可用；新提示词自然进入新缓存命名空间。已有书库、原文快照、偏好和媒体不被批量改写。
- [x] 三个提供方使用一致的阶段契约；原有实际请求形状/安全约束、模型、推理档位、凭证和付费路径不变。
- [x] 通过相关契约和全量本地测试、类型检查及 lint；使用相同输入、模型与档位完成代表性文字前后对比，明确记录范围、质量判断和局限，不以字符串长度下降代替质量验证。

## 边界

这次整理生产提示词及其拼装方式。画风定义是创作参数，保留其视觉意图；历史兼容文本不做美化。没有“所有复杂故事必须 60–80 幅”的新规则。不恢复用户详略选项，不修改推荐确认流程、隐藏偏好继承策略、调度器、持久化结构、认证或模型集成。不重生成书架，不生成图片，不构建 Docker 或桌面包，不推送。

官方依据：https://developers.openai.com/api/docs/guides/prompt-engineering （清晰分段、输入边界、代码版本化及评测）。
