# 增量故事库与主题匹配

现在的扫描由主题驱动，换主题要重新理解原文，找到的故事也无法跨主题复用。将稳定的原文理解和变化的推荐判断拆开：逐篇识别完整故事并持久化，再根据主题筛选；首次阅读逐步积累，以后优先复用。

- [x] 本地原文扫描不接收用户主题或制作偏好，逐篇产出完整故事的标题、不剧透简介、含因果与结局的摘要、可核对原文范围；不匹配当前主题的故事同样入库。支持完整主故事及严格包含的小故事，拒绝同范围改名和交叉重叠碎片。
- [x] 不预扫描全书；先匹配已有库，必要时从共享阅读位置继续识别，找到符合主题的一篇即返回。保留选中/离开停止、跨章未完事件与阅读位置恢复。
- [x] 主题判断读取通用摘要，输出符合、不符合或需核对；符合时同时给出有事件依据的匹配理由和完整拟改编摘要，范围不变可复用通用摘要。需核对时使用原文复核，不把未知当不符合。只返回资料完整的明确符合候选，失败保留故事库。
- [x] 故事库跨主题与任务复用、重启后保留；主题判断及匹配理由/拟改编摘要单独缓存，新增故事补充判断。相同主题重复查找不重复已完成的原文识别或判断。原文版本、范围、提取契约和有效模型配置正确隔离；匹配契约变化不重扫通用库，旧布尔回执不冒充完整制作摘要。
- [x] 旧主题缓存不冒充通用库的完整覆盖，保留旧文件及已保存任务候选；新目录从可证明的位置起步。并发主题共享提取，主题判断彼此独立；取消一个读者不终止其他读者需要的共享工作。
- [x] Codex、Gemini、OpenAI 均支持提取、带理由/摘要的主题判断及摘要核对。匹配沿用 suggest，摘要核对合并进已有画幅建议调用并沿用 frames，不新增凭证、依赖或配置项。非本地书名/URL维持已有能力，本次通用库限本地可信原文。
- [x] 主题模式和原典模式通过选题/制作确认流程创建的新任务都必须有完整摘要，直接选择原典故事也不能因跳过匹配而缺摘要。主题候选的拟改编摘要和理由持久保存并绑定故事；制作准备对照真实原文核对并修正。直接原典或旧式推荐无完整摘要时，在同一准备调用中依据原文补齐实际行动、推进及结果，不把设局目的/简介当完整摘要。保存核对结果后才能确认制作；重选/重启/失败重试不串篇。升级前已有分镜的历史任务仍可继续，已生成故事不自动重做；尚未开始分镜且缺摘要的按下述兜底先准备摘要。
- [x] 短篇分镜、长篇提纲、分批细化以及后续审核/修订均参照核对后的摘要，同时读取原文；继续遵守既有开场、节奏、完整因果、静态画面和连续性规则。主题模式按主题、匹配理由及摘要检查有原文依据的呈现，不再把主题仅限于标题/结语；原典故事/忠于原文模式按原文本身主线和意味展开，不强套主题。两种模式都以原文核实人物、言行、因果及结局，冲突以原文为准。摘要不替代 verifiedOriginal.text 或混为原文。
- [x] 统一以完整摘要指导编排，不另设“设局”资料项。原先“设局”意图落实为第一页开场规则：结合摘要，从原文中提取理解开局所需的背景、人物关系和眼前处境做开场；不照搬完整摘要，不提前泄露后续结局，审核保留此要求。
- [ ] 类型检查、lint、完整单元/集成测试及修正后的受控端到端用例通过，记录真实推理/浏览器证据的边界。
- [ ] 故事、分镜/提纲、编辑/版本快照、接口、展示及ZIP导出统一使用 `summary`，运行时不再读写 `hook`，不保留别名。新摘要允许完整叙事长度；初始空草稿可为空。已核对的制作摘要进入分镜元数据，不在分镜阶段另写引子。
- [ ] 升级迁移已有SQLite故事列、任务中的plan/draft/outline/版本基线及媒体JSON中的旧字段，保留有效的现有summary，否则将旧文字原样移至summary并删除hook；不把旧引子标成已核对摘要，不触发模型重写或重做图片。迁移可重启重试，旧数据库与完整源文件不丢失；迁移历史SQL保留以支持升级。
- [ ] 对实际已配置书库先做一致性备份，再执行同一升级迁移；记录迁移前后数量与无hook检查。缓存中已有summary保持，只有hook的JSON按同一规则迁移，不清空通用库。

不做：全书离线预处理、向量数据库、嵌入检索、主题同义词归并、自动后台扫完整书、SSE、新增界面流程或桌面/Docker打包。允许将现有引子展示/编辑替换为摘要。冷启动多一次轻量主题判断是代价，跨主题复用是收益；不承诺没有真实模型证据的延迟或准确率数字。

主题与直接原典流程在准备时核对摘要；用户后续要求将“没有摘要则先做”扩展到所有尚未开始的分镜入口，包括旧式非intake任务。不改为intake交互，缺摘要时在编排前新增必要的准备步骤。

`!!` 修正：原实现将摘要排除在分镜输入之外，未满足“摘要指导主线、原文支撑细化”的用途。以上相关标准已重新打开；之前846项及3项E2E只证明修正前行为，不作为本轮完成证据。保持后端范围，不增加界面、付费实测或打包。

后续明确修正：用户要求“Hook 改成 summary”，本轮统一字段与实际数据；旧文字原样迁移不等于语义补全。新intake任务在分镜前准备完整摘要，分镜保存时复用核对结果；旧式API缺摘要时也先准备摘要；有已保存完整分镜的历史故事不自动重做。上述历史“后端范围”由本轮必要的现有展示/编辑字段替换扩展。

- [ ] 所有新开始的短篇分镜及长篇提纲入口，都先检查是否已有摘要；缺少时先依据原文生成并保存，成功后才调用编排。原文或摘要失败不调用编排/图像，重试复用已保存原文/摘要；普通读取不触发生成。已确认的任务不因自动补摘要重新要求确认，已有提纲/分镜中的summary可复用，已有成品不重做。
