# 增量故事库与主题匹配

现在的扫描由主题驱动，换主题要重新理解原文，找到的故事也无法跨主题复用。将稳定的原文理解和变化的推荐判断拆开：逐篇识别完整故事并持久化，再根据主题筛选；首次阅读逐步积累，以后优先复用。

- [x] 本地原文扫描不接收用户主题或制作偏好，逐篇产出完整故事的标题、不剧透简介、含因果与结局的摘要、可核对原文范围；不匹配当前主题的故事同样入库。支持完整主故事及严格包含的小故事，拒绝同范围改名和交叉重叠碎片。
- [x] 不预扫描全书；先匹配已有库，必要时从共享阅读位置继续识别，找到符合主题的一篇即返回。保留选中/离开停止、跨章未完事件与阅读位置恢复。
- [ ] 主题判断读取通用摘要，输出符合、不符合或需核对；符合时同时给出有事件依据的匹配理由和完整拟改编摘要，范围不变可复用通用摘要。需核对时使用原文复核，不把未知当不符合。只返回资料完整的明确符合候选，失败保留故事库。
- [ ] 故事库跨主题与任务复用、重启后保留；主题判断及匹配理由/拟改编摘要单独缓存，新增故事补充判断。相同主题重复查找不重复已完成的原文识别或判断。原文版本、范围、提取契约和有效模型配置正确隔离；匹配契约变化不重扫通用库，旧布尔回执不冒充完整制作摘要。
- [x] 旧主题缓存不冒充通用库的完整覆盖，保留旧文件及已保存任务候选；新目录从可证明的位置起步。并发主题共享提取，主题判断彼此独立；取消一个读者不终止其他读者需要的共享工作。
- [ ] Codex、Gemini、OpenAI 均支持提取、带理由/摘要的主题判断及摘要核对。匹配沿用 suggest，摘要核对合并进已有画幅建议调用并沿用 frames，不新增凭证、依赖或配置项。非本地书名/URL维持已有能力，本次通用库限本地可信原文。
- [ ] 主题模式和原典模式的新制作任务都必须有完整摘要，直接选择原典故事也不能因跳过匹配而缺摘要。主题候选的拟改编摘要和理由持久保存并绑定故事；制作准备对照真实原文核对并修正。直接原典或旧式推荐无完整摘要时，在同一准备调用中依据原文补齐实际行动、推进及结果，不把设局目的/简介当完整摘要。保存核对结果后才能确认制作；重选/重启/失败重试不串篇。升级前无摘要的历史任务仍可继续，已生成故事不自动重做。
- [ ] 短篇分镜、长篇提纲、分批细化以及后续审核/修订均参照核对后的摘要，同时读取原文；继续遵守既有开场、节奏、完整因果、静态画面和连续性规则。主题模式按主题、匹配理由及摘要检查有原文依据的呈现，不再把主题仅限于标题/结语；原典故事/忠于原文模式按原文本身主线和意味展开，不强套主题。两种模式都以原文核实人物、言行、因果及结局，冲突以原文为准。摘要不替代 verifiedOriginal.text 或混为原文。
- [ ] 统一以完整摘要指导编排，不另设“设局”资料项。原先“设局”意图落实为第一页开场规则：从摘要选取理解开局所需的背景、人物关系和眼前处境，对照原文展开；不照搬完整摘要，不提前泄露后续结局，审核保留此要求。
- [ ] 类型检查、lint、完整单元/集成测试及修正后的受控端到端用例通过，记录真实推理/浏览器证据的边界。

不做：全书离线预处理、向量数据库、嵌入检索、主题同义词归并、自动后台扫完整书、SSE、额外界面或桌面/Docker打包。冷启动多一次轻量主题判断是代价，跨主题复用是收益；不承诺没有真实模型证据的延迟或准确率数字。

`!!` 修正：原实现将摘要排除在分镜输入之外，未满足“摘要指导主线、原文支撑细化”的用途。以上相关标准已重新打开；之前846项及3项E2E只证明修正前行为，不作为本轮完成证据。保持后端范围，不增加界面、付费实测或打包。
