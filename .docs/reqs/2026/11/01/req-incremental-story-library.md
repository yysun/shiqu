# 增量故事库与主题匹配

现在的扫描由主题驱动，换主题要重新理解原文，找到的故事也无法跨主题复用。将稳定的原文理解和变化的推荐判断拆开：逐篇识别完整故事并持久化，再根据主题筛选；首次阅读逐步积累，以后优先复用。

- [ ] 本地原文扫描不接收用户主题或制作偏好，逐篇产出完整故事的标题、不剧透简介、含因果与结局的摘要、可核对原文范围；不匹配当前主题的故事同样入库。支持完整主故事及严格包含的小故事，拒绝同范围改名和交叉重叠碎片。
- [ ] 不预扫描全书；先匹配已有库，必要时从共享阅读位置继续识别，找到符合主题的一篇即返回。保留选中/离开停止、跨章未完事件与阅读位置恢复。
- [ ] 主题判断读取故事摘要，输出符合、不符合或需核对；需核对时使用该故事原文复核，不把未知当不符合。只返回已明确符合的候选；失败保留故事库，可重试。
- [ ] 故事库跨主题与任务复用、重启后保留；主题判断正反结果单独缓存，新增故事补充判断。相同主题重复查找不重复已完成的原文识别或主题判断。原文版本、范围、提取契约和有效模型配置正确隔离；改变主题匹配契约不使原文识别失效。
- [ ] 旧主题缓存不冒充通用库的完整覆盖，保留旧文件及已保存任务候选；新目录从可证明的位置起步。并发主题共享提取，主题判断彼此独立；取消一个读者不终止其他读者需要的共享工作。
- [ ] Codex、Gemini、OpenAI 均支持新的提取与主题判断；沿用现有 suggest 推理档位，不新增凭证、依赖或配置项。非本地书名/URL维持已有查找能力，本次通用库限本地可信原文。
- [ ] 选定故事后，画风建议、原文准备及分镜继续以该故事对应的真实原文和章节上下文为依据，不用目录摘要代替原文；制作确认门槛保持。
- [ ] 类型检查、lint、完整单元/集成测试及新流程的受控端到端用例通过，记录真实推理/浏览器证据的边界。

不做：全书离线预处理、向量数据库、嵌入检索、主题同义词归并、自动后台扫完整书、SSE、额外界面或桌面/Docker打包。冷启动多一次轻量主题判断是代价，跨主题复用是收益；不承诺没有真实模型证据的延迟或准确率数字。
