# 保存后用于新任务，无需重启

用户将文本设为Codex、图片设为Gemini，界面却报告丢失密钥并要求重启。密钥实际来自启动环境；保存校验只认数据库，界面也混淆了保存值与当前模型实例。用户已明确选择：配置保存后用于新任务，正在执行的任务保留原配置，不再增加重启按钮或重启接口。用户明确要求的Gemini密钥已通过生产API保存数据库，同时保存Codex文本/Gemini图片（revision5）。

- [x] dev、CLI浏览器和desktop服务从共享数据库解析下一项生产任务的提供方、模型、推理及密钥，不重启HTTP/应用/数据库/生产协调器。正在执行的生产步骤固定原提供方、错误格式与超时，后续步骤采用新配置。
- [x] 明确已存密钥与有效启动覆盖的区别，不返回密钥原文、不自动持久化其他环境密钥；keep按覆盖优先级验证，空/非法覆盖不能被已存密钥掩盖。
- [x] 设置页移除重启要求和重启操作，保存成功明确“已保存，新任务使用此配置；正在执行的任务继续原配置”。摘要说明新任务配置；保存/重新读取按钮含义清楚。启动覆盖仍明确显示且保留既有优先级。
- [x] 只读/缺密钥阻止新付费任务，变为可用后无需重启即可派发；已完成生成的本地发布可继续。保留退出等待、发现缓存settle、严格patch/修订/网络边界与显式配置绕过损坏store的既有契约。
- [x] 用隔离数据与合成提供方验证生产任务新旧配置隔离、缓存/只读/错误/密钥/退出、实际服务API与表单，并执行影响计划和独立审查；同步文档/技能。最终核对真实服务新任务配置为Codex文本/Gemini图片，数据库保留Gemini key，不发起真实推理。

不加重启API或任意进程控制，不删除正常桌面生命周期控制，不更改数据库格式，不缓存凭据到新位置，不重设计其他页面。
