# CLI 启动并调用书库服务

Skill 操作桌面正在使用的书库时，最基础的查阅和改名也会返回书库占用。用户需要 CLI 识别同库的服务，必要时自动启动本机服务。书库仍只有一个持锁方。

- [x] 两个 CLI 同时访问空闲书库时，只发布一个可用服务实例。两条命令都成功，且查询不调用模型。
- [x] 桌面或浏览器服务已打开书库时，CLI 可以读取书架、改名、选题、确认、制作、编辑、继续及恢复同一故事。浏览器的下一次读取能看见修改。CLI 的保存命令仍只保存，开始推演必须有显式制作授权。
- [x] CLI 记录已就绪服务的实际本机 URL，连接时验证实例身份。旧端口被复用或服务启动失败时，CLI 不把业务请求发给错误服务，不绕过独占锁，并给出可恢复的结果。
- [x] 自动启动无需打开桌面、浏览器、隧道或交互配置。仅绑定回环地址，最后一条请求后自动退出。服务记录和身份凭据不进入备份和命令输出。
- [x] 服务自动启动时复用现有命令行为。独立 CLI 的制作、暂停和重试判定保持由生产 DAG 执行。同库服务已在线时，`run` 复用它的调度器。达到审片停点后，目标故事不会发图，用本版或支持该协议的新版服务重启也等明确继续操作。降级到早于该行为的版本不会保留 CLI 的停点约定。不影响其他故事。若目标已经有绘图任务在途，有限停点报告冲突。
- [x] 无需服务的帮助、技能管理、预览、导出和维护入口保持原能力。接入原本就在线的浏览器或桌面服务时，并行连接的桌面和 CLI 使用同一应用与生产调度器。手动服务保持其运行时配置，由原入口管理生命周期。

现有桌面后台制作会按读者授权派发，CLI 的保存与 `run --until` 有不同的派发边界。自动启动的服务承接现有完整 CLI 制作，在线执行 `run` 时由当前服务的调度器按目标故事限制派发。已有读者命令记录保存 CLI 提交和有限运行的继续意图。无需增加书库表、永久配置、公开路由或 DAG 预检。

- [x] 完成空闲书库的在线备份和在线来源库复制。目标与来源正常在线时保持同一份正式快照语义。服务有活跃制作、索引或其他书库写入时，备份拒绝并保留运行状态，任务收尾后重试成功。系统强制退出仍按既有清理管道释放资源。
- [x] CLI 保存或有限运行留下的等待阻止了制作时，桌面和浏览器把该故事显示为「已保存，等待继续」，所属步骤提供「继续制作」。读者继续后解除等待并恢复后台制作，已有结果保留；CLI 命令仍在处理该故事时继续返回冲突。CLI 的 `run` 仍可直接推进同一故事。
- [x] 停止、重启或退出服务时若有进行中的任务，服务立即停止领取新任务并拒绝新请求，等已领取的步骤保存后自动停止或退出。等待期间控制台显示等待状态，并提供「立即停止」或「立即退出」。托盘「退出拾趣」、控制台退出和 macOS ⌘Q 使用同一流程；浏览器服务第一次 Ctrl-C 等待，再次 Ctrl-C 立即停止。系统注销、关机和 SIGTERM 仍立即释放。下次启动时制作按原授权继续，不需要逐篇恢复。
- [x] `CHANGELOG.md` 的 0.18.0 记录本故事的读者可见改动。
