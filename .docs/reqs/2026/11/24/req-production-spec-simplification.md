# 制作规范精简需求

## 问题与目标

[制作 DAG](../../../../story-production-dag.md) 和[制作生命周期](../../../../story-production-lifecycle.md)经多轮试错形成，现有 59 个验收场景和约十处状态来源。基于指纹的有效性与免费复用是产品价值所在，但不少规则只服务于旧数据兼容、低频边角或内部记账。它们让状态维度、故障种类和读者动作成倍增加，修复提交也大多落在这些边角上。

同一份故事状态还分散在约十处存储，几处都自认权威：故事行上的旧状态机字段、`document.intake`、`document.dag`、由 `dag` 生成的 `plan`/`images` 投影、自带依赖图的任务表、故障表、命令回执、阅读需求等。生命周期视图要把它们重新拼起来，大量代码只为让它们保持一致。

目标：

- 删去下列 11 项规则，或把它们并入更简单的规则，读者可见的损失尽量小（一类、二类）；
- 让每项状态只有一个来源，所有视图与调度从同一推导得出（三类）。

两部分在同一次书库升级中交付。保留的核心规则不变（见「保留的规则」）。本需求只规定**结果**，具体表结构和模块划分由计划决定。

## 精简范围

### 一类：直接删除

**1-1 旧规则记录与旧版转换路径**

- 现状：转换得到的「旧规则」产物、结论、放行、人物和验收条目在运行时单独判断。读取时还能用 `adopt()` 补做转换。`visualReview` 仍供旧文档读取。旧版横图 DAG 节点和「旧版横图手动接续」仍然存在。
- 结果：
  - 运行时只有一套规则。升级时把旧记录一次性转为当前规则下的等价记录，例如旧审核通过或旧放行记为绑定当前内容的放行。此后它们与新记录一样，输入一变就失效。
  - 升级后不再在运行时转换。无法转换的故事保留原数据，书架标为需要处理并附诊断，不会在读取时补做转换。
  - 旧稿的单条无名人物设定转为普通人物条目，原先没有记录入画人物的画幅明确记为「全部人物入画」。此后运行时不再保留「未记录则按全部计算」的分支。
  - 删除旧版横图 DAG 节点及其运行时接续路径。升级时，带原授权且未完成的旧版横图请求转为独立横图流程中「已暂停」的请求，并采用绑定原输入的可读付费结果。读者从标准横图入口恢复，不再有单独的旧版接续入口。这一条取代[独立横图](req-standalone-landscapes.md)中「旧流程由读者手动接续」的实现方式，读者能做的事不变。

**1-2 故障随修订延续**

- 现状：提交修订时逐个比对上一版的故障，或延续、或放弃、或「待匹配」。延续的故障不因「继续制作」获得恢复授权。
- 结果：
  - 新版本不继承上一版的故障。上一版的故障和恢复请求留在上一版。
  - 新版中输入仍有效的产物照常复用。缺失、不可读或失效的产物，在「继续制作」后按普通工作重新生成，其中包括上一版确认丢失的图片，和上一版被内容拦截、输入未变的画幅。
  - 保存预览列出「继续后将重绘的画幅」，确认丢失的画幅单独标明。
  - 生命周期去掉故障状态「待匹配」。

**1-3 阅读需求模式**

- 现状：
  - 故事有 `reader` 和 `background` 两种生成模式，`reader` 模式要靠浏览器续期的阅读需求才付费。
  - 阅读位置决定预读范围（当前幅之后 6 幅）。
  - 本地发布期间有 15 秒的让位规则。
  - 还保留旧的 `legacy-advance` 需求。
- 结果：
  - 已确认的制作只有一种模式：读者控制为「进行」时在后台推进。
  - 待绘画幅的优先级：读者正在打开的故事优先，同一故事内按幅序。取消逐页预读窗口和发布让位规则。
  - 取消「切换后台」动作，生命周期和书架不再区分阅读模式与后台模式。
  - 候选查找仍只在读者停留于候选选择界面时付费。查找的这道门槛保留。

**1-4 「基于旧输入」与「使用旧参考」标记**

- 现状：核对依赖的上游变化后，下游产物带上「基于旧输入」标记，相关结论随之过期。另一种情况是首幅被替换后，其余画幅显示「使用旧参考」。两种标记都要持续记录，并按专门规则解除。
- 结果：
  - 取消这两种持久标记及其解除规则。
  - 原核对依赖只保留**生成顺序**：画面描述等本幅叙事分镜就绪后才生成，非首幅等首幅（或书籍星标参考）就绪后才绘制，首幅重做期间需要重绘的其余画幅等新首幅完成后再绘制。
  - 一致性改由审片负责：逐幅结论硬绑定本幅与相邻画幅的叙事分镜和画面描述，全篇结论见 2-1。
  - 结语候选、幅数与结构核对不再因叙事分镜文字变化而过期。幅数与结构核对仍在提纲、画幅身份序列、制作要求、详略策略或审核意见变化时重做。
  - 读者重绘或替换首幅时，确认界面直接提供「同时按新首幅重绘其余 N 幅」。读者不选，之后也不再提示。

**1-5 审片范围外建议**

- 现状：审片对允许清单之外的发现记为「建议」，显示在画幅或条目上，下次产出结论时消失。
- 结果：不再保存或显示建议。审片返回的允许清单外判断直接丢弃，不替换任何结论，也不触发修订。

### 二类：合并为更简单的规则

**2-1 验收条目登记与两阶段审片**

- 现状：
  - 每条验收要求先经一次登记调用，确定范围（全篇或逐幅）和依据（叙事、画面、顺序、标题与结语，可多选）。
  - 审片分两个阶段，第二阶段专审依赖选定结语的条目。
- 结果：
  - 取消登记调用、条目的范围与依据，以及第二阶段。
  - 每轮审片最多一次调用，产出失效的逐幅结论和**一条全篇结论**。全篇结论覆盖叙事完整性、标题与结语（读者没有确认时同时选定），以及全部验收条目的逐条判断：通过、未通过或无法判断，各附依据。
  - 全篇结论硬绑定：原文、梗概、两项要求、提纲、画幅身份序列、全部叙事分镜与画面描述、画风、标题与结语候选及读者确认的结果、审核意见，适用时还包括通过的幅数与结构核对。任一画幅的文字变化都会使它失效。
  - 逐幅结论不再判断验收条目。未通过的验收条目指出相关幅号或「全篇」，供定向修订使用。
  - 验收条目仍是每行一条、最多 20 条。「无法判断」仍以要求冲突为由阻断绘图。

**2-2 候选人物与入画人物**

- 现状：叙事分镜产出「候选人物」，作为画面描述的核对输入。手改配文后要按名字和别名重新匹配候选人物，编辑器还会提示「某人被提及」。
- 结果：
  - 取消候选人物。叙事分镜调用不再产出人物名单，手改配文不再匹配人物，也不再提示提及。
  - 画面描述调用把全部人物设定作为来源（不参与有效性），产出本幅「入画人物」。
  - 入画人物仍是本幅绘图的硬输入。改一个人物，只影响该人物入画的画幅。手改画面描述后，仍按名字和别名把新出现的人物并入入画人物。

**2-3 结构修订的画幅身份**

- 现状：合并后沿用第一幅的身份，拆分后第一段沿用原身份；手改和重绘说明随身份保留，内容被改写时丢弃。
- 结果：
  - 结构修订中内容未被改写的画幅保留身份，被合并、拆分或改写的画幅一律取得新身份。
  - 手改和重绘说明只随保留的身份延续。
  - 图片复用照常按绘图输入指纹判断，与身份无关。
  - 手改保护不变：自动结构修订会删除或改写含手改的画幅时，不提交结果，停在「需读者处理」。

**2-4 审片放行动作**

- 现状：「明确放行」处理阻断的结论。「跳过本次审核」用于审核调用失败的情况，要求先暂停或等待继续，并按另一套依据绑定。
- 结果：
  - 合并为一个读者动作「仍然绘图」。审片有阻断结论，或审核调用（含幅数与结构核对）失败且稿件齐备时可用。它对当前所有待定或阻断的结论生效，也覆盖尚未通过的幅数与结构核对，不要求先暂停。
  - 逐幅结论的放行只绑定该幅结论的输入；全篇结论的放行绑定全篇结论的输入。所以修改别的画幅不会撤销某一幅的放行，任一画幅文字变化会撤销全篇放行。
  - 尚未选定标题与结语时，读者在此动作中选定。
  - 审核调用进行中，此动作不可用。

**2-5 两项要求字段的状态**

- 现状：制作要求和验收要求各有四种状态：「建议尚未生成」「采用本篇建议」「用户填写」「用户明确留空」。
- 结果：
  - 每个字段只保存文字和「读者是否编辑过」。
  - 未编辑的字段随准备结果更新：准备完成时填入建议，替换选题后改用新选题的建议。编辑过的字段（包括清空）保持不变。
  - 界面区分「等待准备建议或准备已暂停」（空且未编辑）和「已留空」（空且编辑过）。
  - 制作确认时固定当前文字，此后建议变化不影响制作。

**2-6 模型快照**

- 现状：制作确认时记录全部模型设置的快照，包括文字、绘图、提供方和推理强度。快照里的服务不可用时，故事等待「应用当前模型设置」。
- 结果：
  - 快照只记录图片提供方、图片模型和绘图参数，保证同一作品各幅画面一致。
  - 文字调用（含推理强度）一律使用调用时的全局设置。
  - 「应用当前模型设置」只更新图片快照。文字服务不可用时按服务级故障处理，不写入各篇。

### 三类：单一来源的存储与推导

**3-1 单一推导**

- 现状：
  - 生命周期视图从故事行、文档、任务与租约、故障、命令回执、删除记录和阅读需求拼出来。
  - 任务表另存一份依赖图，与 DAG 重复。
  - 故事行上仍有旧线性状态机字段：`state`、`error`、`step_key`、`step_attempts`、`lock_token`、`lock_until`、`generation_mode`。
- 结果：
  - 一个纯推导，输入为当前版本的输入、产物、执行尝试、读者授权和控制。它同时给出：可运行工作、在途工作、阻断及原因、需读者处理、完成判定、阶段和可用动作。
  - 调度、生命周期、详情、书架、CLI 和测试都读这一推导，不再有各自拼装状态的路径。
  - 不持久化依赖图。可运行工作每次由推导得出。
  - 删除上列旧状态机字段。读者控制（进行、暂停、停止及暂停原因）仍单独保存，因为它是读者的决定。
  - 为书架扫描或调度索引保存的派生摘要（例如是否完成）须与推导结果在同一事务写入。授权、调度和生命周期判断一律不读它。

**3-2 产物在故事家族内按输入共享**

- 现状：新修订复制上一版的 `dag` 和图片文件到新版目录。迟到结果只归派发时的版本；输入已变的结果直接丢弃，即使另一版本正需要同样的输入。
- 结果：
  - 产物以「节点、粒度键、硬输入指纹」为身份，在同一故事家族内只保存一份。各版本按自己的当前输入取用。
  - 新修订不复制产物，也不复制图片文件。
  - 迟到结果照常保存为家族产物，任何输入相同的版本都可复用。它永远不会覆盖或替换某个版本已采用的较新产物。
  - 产物只增不改：手改、修订和换画风都产生新产物，旧产物保留，供历史版本阅读。
  - 已有图片的访问地址、阅读器显示和导出结果不变。导出的 WebP 仍按「Story Export」规则逐字节保留。
  - 「复制」和「复制为草稿」产生另一个故事家族，与原作互不影响：删除原作后，副本仍可完整阅读和导出。
  - 某个产物的图片文件确认丢失时，所有引用它的版本都读不到这幅图。故障仍按 3-3 只出现在发起尝试或核对的版本中。

**3-3 执行尝试统一记录**

- 现状：任务表与故障表各有状态，并要在同一事务中互相同步；尝试次数、中断次数、故障和恢复回执分布在多列与多表。
- 结果：
  - 每次执行（包括被领取、付费发送、成功、失败、拦截和中断）记为一条执行尝试，属于发起它的版本和目标。
  - 故障、自动尝试次数、中断次数、修订额度用量和恢复状态都由执行尝试与读者授权推导，不单独保存需要同步的故障状态。
  - 故障只在发起尝试的版本中出现，与 1-2 一致：新版本不继承上一版的尝试或故障。
  - 删除运行时的故障延续代码（现 `server/dag-revision-faults.ts`）。命令幂等与回执重放保持不变。

**3-4 不保存投影**

- 现状：`document.plan` 和 `document.images` 是由 `dag` 生成的 v1 形状投影，每次保存都要与 `dag` 一起写入；阅读、导出、复制、CLI 等读取方读投影。
- 结果：
  - 不再保存这两份投影。所有读取方从同一来源取得画幅顺序、文字和图片。
  - 阅读器、导出、复制和 CLI 的输出与升级前一致。

**3-5 一次书库升级**

- 结果：
  - 一、二、三类的全部数据变化在一次书库格式升级中完成，格式版本提升。
  - 所有现已支持的合并书库格式（格式 1、2、3，即 0.8 及以后）都由新版本在一次打开中直接升级到新格式，中间不需要先经 0.16.x。整个过程只做一次整库备份。合并前的 0.2–0.7 应用打开已合并书库时，仍由原保护触发器拒绝（`BACKUP_APP_TOO_OLD`）。保留已支持的历史书库转换和离线导入入口。
  - 历史迁移的代码钩子（现 `server/dag-migration.ts`、`server/dag-fault-migration.ts`，分别对应 0025 与 0027）及其使用的 v1 转换代码（现 `lib/production-dag/convert.ts`）保留，但只在迁移边界使用，运行时不引用。
  - 格式 3 书库中仍是 v1 文档的故事（0025 转换失败、目前靠运行时 `adopt()` 接管的）由本次升级在迁移边界用同一转换补做，然后按 1-1 转为当前规则。仍无法转换的，按 1-1「无法转换」处理：保留原数据，书架标为需要处理。
  - 离线旧库导入（`server/import-legacy.ts`）产出的书库同样由新版本直接升级。
  - 新建书库直接得到新格式。
  - 调度节拍仍只读取上次检查后有变化的故事，不因取消投影或依赖图而退回到逐篇读取全文（见[调度内容修订号](../19/req-production-tick-content-rev.md)）。书架与详情轮询读取的数据量也不因此增加。

## 保留的规则

以下规则不在本次范围内，行为保持不变：

- 产物有效性：内容可读，且硬输入指纹与当前上游一致。复用、失效和重做范围都由这条规则推导，包括按绘图输入指纹跨画幅、跨版本复用图片。
- 逐幅审片结论：只复核受影响画幅及其相邻画幅。
- 每个保存的修订有 20 次自动修订额度，「继续自动修复」再给 20 次。
- 手改字段不会被静默覆盖。
- 稳定画幅身份；重排本身不使图片失效。
- 「保存修改」后「已保存，等待继续」，由「继续制作」授权接续。
- 暂停与停止；故障只阻断依赖它的工作；内容拦截不自动重试；服务级故障。
- 付费发送前的授权核对；命令幂等与回执重放；迟到结果不会替换任何版本已采用的产物（按 3-2 保存后可被输入相同的版本复用）。
- 横图作为独立的可选印刷工作。
- 制作确认门槛、重新准备，以及候选查找的独立轮次。

## 约束

- **书库升级。** 1-1、1-2、1-3、2-1、2-2、2-5、2-6 和全部三类会改变已保存的文档、任务或故障数据，须遵守「Canonical Story Storage」：
  - 用 `drizzle/` 普通迁移，经 `ensureLibraryReady()` 在已核验的整库备份之后原地应用，并更新 `db/library-format.json` 的 `latestMigration`。
  - 旧应用读不懂新文档（例如缺少 `visualReview`、旧规则标志或候选人物），所以须提升 `schemaVersion`，让旧应用拒绝打开。
  - 文档中写明新格式所需的最低应用版本。回退只能用升级前的整库备份与配套应用，恢复到另一目录。
- **按当前规则保存的数据同样转换。** 不只是旧规则记录，0.15.0 之后按现行规则保存的故事也要转为新结构：
  - 全篇叙事结论与各条验收条目结论合成一条全篇结论。全部通过记为通过；任一阻断且未放行记为阻断；已放行的记为对全篇结论的放行；仍有未审部分的记为待审。
  - 删除条目登记、第二阶段记录、候选人物、建议和「基于旧输入」标记。
  - 逐幅结论及其放行原样保留。逐幅结论里的验收条目判断移除，不改变它的通过与否。
  - 因此，升级时正在审片的故事继续后最多再做一次审片调用。
- **任务记录。** 升级时，已取消调用（条目登记、第二阶段审片等）的排队任务作废，其余排队任务按新规则重新推导。已付费、输入仍有效且结果可读的任务结果照常采用，不重新付费。
- **升级不产生付费调用。** 转换不调用模型。升级前处于 `reader` 模式且未完成的故事，升级后控制为「读者暂停」，不在后台自动开始付费工作。其余故事保持原控制状态。
- **已完成作品。** 升级后仍判定完成，可阅读、可导出，书架版本与导出文件名不变。
- **CLI 与技能同步。** 动作改名或合并（「仍然绘图」、取消「跳过本次审核」、取消阅读需求模式等）须在同一变更中更新 CLI 帮助、`skills/shiqu/SKILL.md` 及受影响的示例。
- **规范文档同步。** 同一变更更新以下文档，删除或改写本需求取消的规则和场景：
  - [制作 DAG](../../../../story-production-dag.md)
  - [制作生命周期](../../../../story-production-lifecycle.md)
  - [故事创建、编辑与队列管理](../../../../story-creation-editing-queue.md)
  - [故事生成状态机](../../../../story-generation-state-machine.md)
  - 用户指南的相关段落
- **生产流程唯一。** 测试和评估工具调用同一套生产实现，不为旧规则保留单独的兼容路径。

## 验收条件

### 一类

- [x] **1-1 旧规则。** 升级一个含以下故事的书库副本后，运行时代码不再出现旧规则分支、`adopt()` 读取时转换或 `visualReview`：
  - 一篇已完成作品；
  - 一篇旧审核通过、正在补绘缺幅的作品；
  - 一篇旧审片阻断后被放行的作品；
  - 一篇含未完成旧版横图请求的作品；
  - 一篇按现行规则审片、全篇叙事结论通过、一条验收条目被放行的作品；
  - 一篇正在等待第二阶段审片的作品。

  升级后：
  - 已完成作品仍判定完成，模型调用数为零；
  - 补绘中的作品只绘制缺幅，不先审片；
  - 被放行的作品内容不变时可继续绘制，改动被放行画幅后放行失效；
  - 未完成的旧版横图请求出现在独立横图入口，状态为已暂停；恢复后先采用可读的付费结果。已有可读横图仍可导出；
  - 现行规则的作品得到一条已放行的全篇结论，内容不变时绘图调用不受影响；
  - 等待第二阶段的作品继续后只做一次审片调用。
- [x] **1-1 转换失败。** 一篇无法转换的故事升级后保留原数据，书架显示需要处理及诊断。读取它不会触发转换，也不影响其他故事。
- [x] **1-2 故障不延续。**
  - 第 2 幅已确认丢图时，只修改第 20 幅画面描述并保存：保存预览列出第 2 幅「已确认丢失，继续后重绘」和第 20 幅；「继续制作」后两幅都绘制。
  - 上一版的故障仍显示在上一版。新版的故障列表为空，直到新版自己出现故障。
  - 生命周期接口不再返回故障状态「待匹配」。
- [x] **1-3 单一后台模式。**
  - 已确认的故事在读者关闭页面后照常推进。
  - 同时打开一篇故事时，该篇待绘画幅先于其他故事派发，篇内按幅序。
  - 升级前 `reader` 模式且未完成的故事，升级后显示「已暂停」，绘图调用数为零，直到读者恢复。
  - 离开候选选择界面后，候选查找不再发出新的付费调用。
  - 生命周期动作、书架和 CLI 都不再提供「切换后台」。
- [x] **1-4 无持久标记。**
  - 手改一幅配文后，结语候选和幅数与结构核对保持有效，不显示「基于旧输入」。本幅及相邻两幅的逐幅结论和全篇结论被复核。
  - 重绘首幅时，确认界面提供「同时按新首幅重绘其余 N 幅」。不勾选时，只重绘首幅，其余画幅保持有效，之后不显示「使用旧参考」；勾选时，其余画幅在新首幅完成后绘制。
  - 新编排时，第 7 幅叙事分镜完成前，第 7 幅画面描述不启动。
- [x] **1-5 无建议。** 一次审片的允许清单只含第 9–11 幅时，返回结果另含对第 30 幅的不通过判断：第 30 幅的结论不变，界面不显示建议，不发生修订或重绘。

### 二类

- [x] **2-1 单次审片。**
  - 首次制作时验收要求含「结语呼应开篇」，不发生登记调用。第一次审片在一次调用中选定结语，并判断包括该条在内的全部验收条目。
  - 手改 15 幅画面描述后继续，审片只调用一次：允许清单含受影响画幅的逐幅结论和全篇结论，其余逐幅结论与放行保留。
  - 验收条目「结尾才揭示身份」：把揭示身份的一幅移到开头，全篇结论复核后该条不通过，并指出相关幅号。绘图调用数为零。
  - 无法判断的验收条目阻断绘图，提示修改要求。
- [x] **2-2 只有入画人物。**
  - 叙事分镜调用记录中不再有人物名单。
  - 一幅配文新增「此时曹操尚在许都」后，入画人物不变，编辑器不提示，绘图调用数为零。
  - 手改画面描述加入一个原本不入画的人物，该人物并入入画人物，本幅图片失效。
  - 修改一个人物的外观，只有该人物入画的画幅重绘。
- [x] **2-3 结构身份。** 结构修订合并第 3、4 幅并拆分第 7 幅，结果中这些画幅都取得新身份。原第 3、4、7 幅的重绘说明在预览中列为将丢弃。未改写画幅的身份、手改和重绘说明保留。只要画面描述等绘图输入相同，新身份画幅也沿用旧图。
- [x] **2-4 「仍然绘图」。**
  - 第 5 幅逐幅结论阻断时，「仍然绘图」后开始绘图。随后手改第 20 幅画面描述，第 5 幅的放行仍然有效；手改第 5 幅画面描述，则第 5 幅放行失效。
  - 审核调用失败且稿件齐备时，同一动作可用且不要求先暂停。尚未选定结语时，读者在此动作中选定。
  - 审核调用进行中，该动作不可用。
  - 界面、接口和 CLI 都不再提供「跳过本次审核」。
- [x] **2-5 字段状态。**
  - 准备期间明确清空验收要求，收到建议后仍显示「已留空」。
  - 未编辑的制作要求填入本篇建议，替换选题后改用新选题的建议。
  - 已有四态记录的故事升级后显示不变。
- [x] **2-6 图片快照。**
  - 制作确认后修改全局图片模型，该故事继续用快照里的图片模型；「应用当前模型设置」之后，只有之后的绘图使用新模型。
  - 修改全局文字模型，该故事之后的文字调用立即使用新模型。

### 三类

- [x] **3-1 单一推导。**
  - 调度、生命周期、详情、书架和 CLI 由同一推导函数取得状态。`tests/production-reader-exits.test.mjs` 与调度测试用同一组输入得到相同结果。
  - 任务记录不再保存依赖。故事行不再有 `state`、`error`、`step_key`、`step_attempts`、`lock_token`、`lock_until`、`generation_mode`。
  - 把派生摘要改成错误值后，授权、调度和生命周期结果不变。
- [x] **3-2 共享产物。**
  - 已完成作品保存一次只改第 20 幅画面描述的修订：新版不复制图片文件，其余画幅直接沿用原产物；第 20 幅重绘后，新版和历史版各自显示自己的第 20 幅。
  - 修订提交后，上一版第 7 幅的绘图才返回，而新版第 7 幅的绘图输入与之相同：新版直接采用该结果，第 7 幅绘图调用数为零。输入不同时，该结果不进入新版，也不覆盖新版已有的第 7 幅。
  - 升级前已有图片的阅读地址可用，导出文件与升级前逐字节一致。
- [x] **3-3 执行尝试。**
  - 一幅图绘制失败两次后成功：尝试记录有三条，故障在成功后解除，无需另写故障状态。
  - 中断后自动尝试次数仍以 3 次为限。
  - 同一请求编号重放时返回原回执，不新增尝试。
  - 运行时代码不再引用故障延续逻辑。
- [x] **3-4 无投影。** 文档不再含 `plan` 与 `images`。阅读器页序、配文、图片地址，以及导出的 `故事.json` 与 `分镜.md`，与升级前一致。
- [x] **3-5 一次升级。**
  - 用格式 1（0.8–0.14）、格式 2（0.15）和格式 3（0.16）的书库副本各升级一次：都在一次打开中直接到达新格式，只做一次整库备份，模型调用数为零。三份副本中同类故事的升级结果与 1-1、3-x 的要求一致。
  - 离线旧库导入的产物可被新版本直接升级。
  - 格式 3 书库中残留的 v1 文档故事升级后转为当前规则；人为制造的无法转换的故事在书架显示需要处理，其他故事不受影响。
  - 运行时模块不导入历史迁移钩子或 v1 转换代码。
  - 新建书库直接可用，格式为新格式。
  - 调度节拍对未变化的故事不读取全文。

### 整体

- [x] **规范与场景。** 制作 DAG 与生命周期文档不再出现被取消的概念，包括：旧规则、候选人物、验收条目登记与依据、第二阶段审片、建议、基于旧输入、使用旧参考、待匹配、跳过本次审核、阅读需求模式。验收场景逐条按「受影响的现有场景」处理。
- [x] **读者出口。** `tests/production-reader-exits.test.mjs` 的维度枚举去掉被取消的状态。每个需要读者处理的状态仍有可点击的操作或不可用原因。
- [x] **升级安全。** 升级在已核验的整库备份之后完成，模型调用数为零。旧版应用拒绝打开升级后的书库。中断后重新升级，结果与一次完成相同。
- [x] **CLI 与技能。** CLI 帮助、`skills/shiqu/SKILL.md` 与生产行为一致。

## 非目标

- 不规定具体表名、列名或模块划分，由计划决定。
- 不改命令回执、删除记录与阅读需求（候选查找门槛）的职责。
- 不改提示词正文、模型选择策略或绘图质量。
- 不改横图的独立印刷流程。只删除旧版横图节点，并把未完成的旧请求一次性转入该流程。
- 不删除逐幅审片、手改保护、修订额度、保存后等待继续、命令幂等或付费发送核对。
- 不提供历史版本恢复、单篇绘图参数编辑、按条目放行等现已不提供的入口。

## 待决问题

无阻断问题。以下取舍已按推荐方案写入，读者如有不同意见可调整：

1. **1-2 对内容拦截同样不延续。** 继续后，输入未变的拦截画幅会再试一次。代价：可能再被拦截一次。
2. **2-1 全篇结论依赖全部画幅文字。** 每轮审片的调用次数不变，但只改画面也会复核全篇，全篇放行也更容易失效。
3. **1-3 升级时 `reader` 模式且未完成的故事改为暂停，** 避免升级后在后台意外付费。
4. **3-5 直接升级所有已支持的旧格式（已决定）。** 0025、0027 的迁移钩子和 v1 转换代码保留在迁移边界，运行时不引用。
5. **3-2 迟到结果可被新版复用。** 这改变了现行规则「迟到结果只归原版本」：已付费的结果不再浪费。由于复用不产生调用，它不需要额外的读者授权。
