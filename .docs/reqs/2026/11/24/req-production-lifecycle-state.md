# 制作生命周期状态需求

## 问题与目标

0.15.0 把制作切换到数据驱动的 DAG。[制作 DAG](../../../../story-production-dag.md#产物有效性) 负责产物有效性、就绪和复用，并规定「不另设进度枚举」。[故事生成状态机](../../../../story-generation-state-machine.md)的执行门槛、故障隔离、命令幂等（第 3 节）以及控制和图片可用性（第 6 节）仍然适用于 DAG 故事，其中按 `nextStep()` 和 `visualReview` 推导的部分只适用于旧故事。两份规范合起来，仍没有完整回答几件事：

- 当前版本处于哪个阶段；
- 读者此刻能做什么，每个动作授权什么；
- 每种故障、阻断和任务结果之后去哪里。

这些状态散落在多处：DAG 门槛标志（`preparing`、`confirmed`、`reprepare`、`resumeUnreviewed`、`skipFrameCheck`）、`dag.continuation`、`generation_control`、`stories.state`、`reader_faults`、`production_jobs`、`library_deletions`，以及旧检查点 `visualReview`。DAG 故事的阻断问题、重试步骤和审核意见编辑仍由 `visualReview` 决定，而 DAG 修订会删除它。当前状态由七处分别推导：`reader-model` 的阶段文字、`production-dag/progress`、`generation-progress`、`production-stages`、`shelf-generation`、服务端快照视图和命令行 `run` 的原因。

切换后的修复提交大多落在这一层。[路径审计](../../../../../.tests/story-lifecycle/evidence/2026-11-24T15-26-35Z-dag-path-audit/summary.md)的 7 个失败用例中，6 个属于生命周期、故障或状态投影。

目标：把上述规范整合为 DAG 时代故事当前版本的**一份权威生命周期定义**，满足三点：

- 各维度取值封闭；
- 每个事件在每种可达状态下都有且只有一条规则给出结果；
- 所有界面和命令行读到同一份状态。

DAG 的产物规则保持不变。分类依据见 [缺陷分类与完整性核查](../../../../plans/2026/11/24/plan-production-lifecycle-state.md)。

## 状态的组成

生命周期状态是若干**推导维度组成的元组**，不是一个扁平枚举。各维度可以同时成立，彼此之间有约束，例如「已完成」不与「修订待继续」同时出现。规范须为每个维度列出全部取值、推导所用的持久数据，以及维度之间的约束。至少包括：

| 维度 | 取值 |
| --- | --- |
| 阶段 | 选题、准备、待制作确认、制作中、已完成 |
| 版本归属 | 当前版、被取代的历史版（包括已完成的被取代版）、已删除 |
| 替换草稿 | 无、打开中 |
| 控制 | 进行、读者暂停、已停止 |
| 修订继续 | 无、修订待继续 |
| 在途收尾 | 有、无（暂停、停止或取代后仍有已领取任务） |
| 需读者处理 | 按原因分别判断的谓词，可同时成立。原因有：审片阻断、修订额度用尽、修订无进展、只能改动手改字段、要求冲突或无法判断、需要重新编排。每个原因带有其目标结论 |
| 故障谓词 | 是否有未解除故障，分别针对必需节点、可选节点（横图）、首幅、本次动作的目标。故障种类为步骤失败、内容被拦截、中断、确认丢图；故障状态为待处理、恢复中、待匹配。种类与状态分开判断 |
| 图片可用性 | 无、某幅待核对、暂时无法核对。确认丢失只作为故障种类，不在本维度出现 |
| 服务可用性 | 可用，或不可用及原因：未配置或只读、快照服务不可用、密钥或登录失效、额度不足、限流退避；另有服务正在停止 |
| 当前活动 | 在执行的任务集合（每项指明调用和画幅，绘图可多幅并行）、排队、没有可运行工作 |

每个条件只属于一个维度。例如「审核调用失败、没有结论」属于故障谓词，不同时出现在「需读者处理」里；审片阻断不再伪装成故障。

规则行须写明每个动作作用于哪些原因和目标。例如「继续自动修复」只针对额度用尽的目标，修改要求只针对要求冲突的目标。

**阶段只由产物决定。** 暂停、修订待继续、需读者处理和故障都是与阶段并存的维度，不是与「制作中」并列的状态，它们本身不改变阶段。「已完成」指 DAG 判定整篇完成：必需产物全部有效可读、可绘图，且必需节点没有未解除故障。因此必需图片确认丢失时，产物变为不可读，阶段由「已完成」回到「制作中」。

**确认后保存制作修改会建立新版本。** 原版本保持原阶段（例如「已完成」），版本归属变为历史版。新版本的阶段由其产物推导：
- 有需要重做的工作时，新版本带有「修订待继续」，直到读者「继续制作」；
- 没有需要重做的工作时，沿用原来的控制状态，阶段可能仍是「已完成」。今天的代码在这种情况下一律设为进行（除非提交时指定暂停），须按此修正；
- 「修订待继续」与控制是两个维度。控制只记录读者自己的暂停或停止。新版本的控制取原版本在提交时的控制值，与「修订待继续」分开保存。今天的代码把等待继续写成 `generation_control='paused'`，与读者暂停无法区分；存储方式可以沿用，但推导时须能区分两者。「继续制作」同时解除修订待继续和读者暂停（[制作 DAG · 保存、暂停与继续](../../../../story-production-dag.md#保存暂停与继续)）；
- 例外是在已完成作品上确认重新生图：新版不带「修订待继续」，立即授权所选画幅绘制。

## 验收条件

### 定义完整

- [ ] **维度与约束。** 规范按上表列出各维度的取值、推导所用的持久数据和维度间约束。不可达的组合由具名约束排除。旧检查点 `visualReview` 只用于旧故事转换。
- [ ] **推导输入明确。** 规范列出推导所用的全部输入：已保存的故事行与文档、故障、任务及其租约、命令回执、删除记录、阅读需求租约、服务可用性和当前时间。同样的输入在任何界面推导出同样的状态。
- [ ] **事件封闭。** 规范列出全部事件：
  - **选题与准备**：查找或继续查找、打开或取消替换草稿、选择或替换选题、恢复准备、重试准备、重新准备、开始制作、确认前保存；
  - **修订**：确认后保存，分为有效修改、规范化后等价的修改和仅展示信息，并包括保存时的手改取舍和过期令牌冲突；以及修改审核意见、继续制作、复制与复制为草稿、指定首幅原图；
  - **控制**：暂停、恢复生成、停止、切换为后台（无变化）、删除与恢复删除；
  - **审片与修复**：继续自动修复、放行审片阻断、审核调用失败时重试审核或跳过本次审核；
  - **故障与图片**：重试故障、在已完成作品上确认重新生图（建立新版并立即绘制）、恢复确认丢失的画幅、重新检查图片、生成或重试横图、应用当前模型设置；
  - **系统**：任务成功、普通失败、内容被拦截、超时或中断、服务不可用与恢复、审片阻断、修订额度用尽、修订无进展、手改冲突、图片待核对、暂时无法核对、确认丢失或恢复可读、迟到结果、服务重启、服务停止，以及并发情形：控制变化与任务领取或结果保存同时发生、并发提交、删除时仍有在途任务。
- [ ] **规则表全覆盖且不重叠。** 规范以「事件 × 守卫条件」的规则行定义转换。守卫条件是对上述维度的谓词，可用通配。每行写明：
  - 各维度的新取值；
  - 本次授权的工作范围；
  - 或者拒绝、HTTP 状态码及读者看到的提示。

  对所有满足约束的可达状态与每个事件，恰好一条规则匹配。
- [ ] **每个阻断都有出口。** 每个「需读者处理」原因、每种故障种类和每种服务不可用原因，都至少有一条规则允许读者执行服务端接受的动作，或说明自动恢复的条件。规范设计了但本需求不提供的入口在表中标为「不提供」，包括：恢复历史版、按身份重排、同时更新画面描述、编辑绘图参数、按条目放行、读者要求的全篇复核、允许自动修订覆盖手改。
- [ ] **显示优先级唯一。** 规范给出多个维度同时成立时的显示规则，并写明多项任务在途或多个原因并存时，按哪条规则选出主显示的那一项，例如最早领取的任务。阶段说明、计时、幅号和可用动作都对应这一项，其余项另行提示。

### 行为一致

- [ ] **一个状态来源。** 对相同的推导输入，以下各处报告同样的阶段、控制、阻断原因、当前活动和可用动作：服务写入回包、轮询读取、书架、故事设置、阅读器、移动端进度和命令行。DAG 故事的阻断问题、可用动作和审核意见编辑不再读取 `visualReview`。
- [ ] **授权在提交与领取时生效。** 共享规则函数决定界面提供哪些动作，但界面显示不构成授权。服务端在以下三处按当时的状态重新判定：
  - **命令提交**：读者命令在写入的同一事务内复核，提交时状态已不满足规则时拒绝，并返回当前状态；
  - **任务领取**：领取任务的同一（同步）事务内，复核由数据库可得的各项：故事行与文档、控制、修订继续与准备代次、删除记录、是否被取代、阅读需求租约与当前时间、该实例的故障（含按指纹匹配）以及跳过审核记录是否仍有效。复核失败则不领取。今天的 `canRun` 在领取事务之外异步执行且不检查故障，这一缺口须消除；异步的 `canRun` 只可作为预筛；
  - **调用前**：沿用现有规则「在领取前和正式调用前验证授权」（[制作 DAG · 版本与并发约束](../../../../story-production-dag.md#版本与并发约束)）。发起模型或绘图调用前再判定一次，包括无法放进同步事务的进程状态与读写检查：服务可用与快照服务、服务是否正在停止、书籍星标参考图、旧参考图、已付费文件是否可读。今天 `run()` 在调用前不检查是否被新版本取代，须由这次判定补上。

  **最后一次判定位于发送边界。** 提供方在发出付费请求前还有准备工作，例如绘图时解析书籍星标参考图（`server/book-image-reference.ts` 的包装）和读取参考图字节（`server/openai-provider.ts` 的 `image()`）。最后一次授权判定须放在这些准备完成之后、发出付费请求之前，文字调用同样如此。准备阶段内提交的暂停、停止、删除或新版本，都在发送前被这次判定拦下。

  各类提供方在各自的付费发送点判定：
  - OpenAI、DeepSeek、Gemini：经注入的 HTTP 传输发出的付费模型或绘图请求；
  - Codex：JSON-RPC 的 `turn/start`。启动进程、`initialize`、读取账号与配置、`thread/start` 都不付费，不算发送；
  - Claude：启动带提示词的命令行进程。

  判定只针对付费的模型和绘图请求，不针对免费的读取（例如原文核对经同一传输发出的抓取）。同一任务发出多次付费请求时（例如提供方内部重试），每一次都在发送前判定。第一次付费请求发出即为「调用已发出」；之后某次判定失败时，停止发出后续请求，已付费的部分作为回执保存，任务按原因处理。

  「调用已发出」的时刻定义为：发送边界的判定通过、付费请求开始发出。在此之后提交的变化都按「调用发出之后」处理，使测试结果确定。测试：让参考图读取（或该提供方发送前的准备）挂起，期间暂停（以及另一用例中提交新版本），放行后断言付费请求次数为零，任务按上面的原因处理。每类提供方适配器各跑一遍，使用替身传输或替身可执行文件。

  调用前判定失败时，按原因处理：
  - 暂停、停止或删除：任务退回排队，不计尝试次数；
  - 被新版本取代或输入已变：任务作废，不发起调用；
  - 服务不可用：任务退回排队，原因进入服务可用性维度。「快照服务不可用」由实时检查得出，不再从失败任务推断；
  - 必需输入确认不可读（星标参考图、首幅参考等）：记为对应种类的故障；
  - 已付费文件或参考暂时无法读取：任务退回排队，不计尝试次数，不重新付费绘制，图片可用性记为「暂时无法核对」。

  并发的先后以数据库提交顺序为准，规则如下：
  - **暂停、停止或删除**：先于领取提交时，任务不被领取；在领取之后、调用发出之前提交时，调用前判定失败，任务退回排队；在调用发出之后提交时，本次调用按原版本收尾，已付费结果照常保存（删除的故事也保存），不领取新任务；
  - **新版本提交**：在调用发出之前提交时，旧任务作废，不发起调用；在调用发出之后提交时，结果只写入原版本，作为原版本的产物和付费回执。新版本按自己的授权安排工作，可能再次付费。这维持「迟到结果只归原版本」，不扩大复用规则；
  - **删除与恢复删除**：删除使控制变为「已停止」。恢复删除后控制仍为「已停止」，须读者明确「恢复生成」才继续，与[故事生成状态机](../../../../story-generation-state-machine.md)第 6 节一致。今天的代码恢复删除后会直接继续制作，须按此修正。

  测试覆盖上述每种先后顺序，并断言付费调用次数。
- [ ] **故障按绘图输入匹配，只有一份实现。** 故障延续、待匹配和放弃的判定在正式路径与测试中使用同一实现，规则如下：
  - 匹配依据节点的硬输入指纹，不依赖画幅身份；
  - 判定时机是新指纹确定之后（包括继续制作时重新编排产生的新指纹）、为该节点领取任何任务之前，不限于提交修订时；
  - **复用先于阻断。** 有可读图片与本幅绘图硬输入相同时，按输入复用，不付费，本幅的匹配故障随之解除。确认丢失的图片标为不可读，不参与复用；
  - **逐幅建立故障实例。** 一项确认丢图故障（来源故障）匹配到**每一幅**仍需成图、且绘图硬输入指纹与之相同的画幅时，为该幅建立一个故障实例，记录来源故障。指纹不同的画幅照常制作。这样一个故障实例仍只对应一个恢复目标和一个画幅，符合[故事生成状态机](../../../../story-generation-state-machine.md)第 3 节；
  - 判定逐幅进行，与新指纹产生的先后无关。一幅指纹不同不会使来源故障被放弃，之后确定指纹的其他画幅仍按它判定；
  - 读者的恢复动作只授权所选画幅的故障实例。其他匹配画幅仍受阻，直到读者分别恢复，或者所选画幅的新图可读后按上面的复用规则免费补上；
  - 来源故障保持「待匹配」，直到当前版本全部仍需成图画幅的绘图指纹都已确定。此时来源记录一定关闭，两种情况都写明：
    - **有匹配**：来源记录关闭，剩余的阻断只由各幅故障实例承担；
    - **没有匹配**：来源记录判为不适用并关闭。

    处于「待匹配」期间，来源故障阻止整篇判定完成，但不阻断其他画幅。来源关闭后不再参与完成判定；
  - **匹配幂等。** 每个（来源故障、画幅、绘图指纹）最多建立一个故障实例。调度器多次运行、服务重启或重复判定，都不会再建立实例，也不会重新打开已解除的实例。读者已恢复、已复用或已解除的画幅故障保持解除，除非该幅的绘图指纹之后变化，并重新与一项仍在「待匹配」的来源匹配。来源一旦关闭，不再与任何画幅匹配：之后输入相同的画幅按可读图片复用，或者正常授权绘制；
  - **指纹变化使实例失效。** 仍未解除的故障实例所在画幅，其绘图指纹之后变化时（例如结构修订或手改画面描述），该实例判为不适用并关闭，与[制作 DAG · 版本与并发约束](../../../../story-production-dag.md#版本与并发约束)的延续规则一致；
  - 不出现无法解析出画幅的孤立故障。故障实例显示于对应画幅；仍在待匹配的来源故障显示为待定的版本级故障。

  测试至少覆盖：一幅匹配一幅不匹配（C015）、两幅新画幅匹配同一指纹、前一幅先确定且不匹配而后一幅匹配、只恢复其中一幅时另一幅在新图可读前仍受阻，以及新图可读后另一幅免费复用并解除故障；有匹配时来源记录关闭、整篇在各幅解除后可判完成；以及解除后多次运行调度器、重启服务，故障不被重建。每种情况都断言付费绘图次数。
- [ ] **服务不可用作为一个状态。** 服务不可用的原因进入上表维度，并有显示优先级和出口。规范为每个取值写明本阶段的数据来源：未配置或只读模式取服务状态，快照服务不可用取快照检查，服务正在停止取服务生命周期。未配置或只读模式下，书架和故事显示原因，不再静默不动。

  过渡期内，密钥或登录失效、额度不足只归故障维度：仍记为逐篇的步骤故障，按错误分类显示原因，出口为「修正配置后重试」。它们在服务可用性维度中标为「保留，当前不可达」，后续需求实现按服务记录后才移入该维度。「限流退避」同样保留、当前不可达。
- [ ] **审计失败项按规范通过。** 下列用例在 [CASES](../../../../../.tests/story-lifecycle/CASES.md) 中由 TODO 转为必须通过：
  - **C010**：绘图中提交规范化后与当前设置等价的修改，不建新版、不暂停，在途任务和授权保持原状；
  - **C011**：第 2 幅故障、第 5 幅在途时，各界面显示正在处理第 5 幅，另外提示第 2 幅待处理；
  - **C013**：在途时改展示名，写入回包与随后的轮询状态相同，阶段说明和开始时间都不闪回；
  - **C014**：修订额度用尽后，界面列出阻断问题，可以修改审核意见，并提供「继续自动修复」。服务端接受并授予新额度，同一请求重放不重复授予；
  - **C015**：见上文故障匹配；
  - **C017**：审核调用失败、没有结论时，提供重试审核，并允许「跳过本次审核」（已确认，见「已确认的决定」）：
    - **前提**：稿件齐备、当前审核故障号匹配，且控制为读者暂停或已停止、或处于修订待继续时（三者都保证跳过后不会立即绘图），可以明确「跳过本次审核」。稿件齐备指所有待定结论的硬输入（含验收条目登记）均有效；
    - **结语**：尚未选定标题与结语时，由读者在跳过时选定，或明确采用列出的默认候选，与放行规则一致。先保存结语选择，再计算绑定；
    - **记录与失效**：跳过记录在审核记录中可见，并同时解除这次审核调用故障。跳过绑定以下内容在跳过时的指纹，任一项变化即失效：
      - 每条待定结论（逐幅结论、全篇叙事结论、全篇验收条目结论）按登记表计算的当前硬输入；
      - **全部**验收条目的登记，包括范围与依据。登记表中的逐幅结论今天不依赖条目登记，跳过记录须单独绑定，否则把条目从「全篇」改为「逐幅」不会使跳过失效；
      - 保存的标题与结语选择；
      - 自动幅数时通过的幅数与结构核对。

      这项绑定只属于跳过记录，不改变普通审片结论的依赖（后者见非目标）。跳过是否仍有效在领取绘图任务和调用前判定，失效时不绘图，故事回到审核调用失败前的待审状态。测试覆盖：跳过后改一条验收条目的登记、改结语选择、改一幅画面描述，各自都在绘图前使跳过失效，且付费绘图次数为零；
    - **绘图**：跳过后保持原控制与继续状态、零绘图。读者暂停或已停止时由「恢复生成」开始绘图，有修订待继续时须「继续制作」；
    - **拒绝**：过期故障号、稿件不齐、非审核故障或未暂停时拒绝。

    CASES 的 C017 与此同步。

### 兼容与文档

  - **实测失败时的回退。** `v0.15.0` 打开书库时只把 SQLite 的 `PRAGMA user_version` 与它支持的 `schemaVersion` 比较，不读取 `minimumAppVersion`，所以只提高 `minimumAppVersion` 拦不住它。须先单独确认，再按项目规则：

## 范围与约束

- 适用于 DAG 时代的故事当前版本、被取代的历史版，以及转换进入 DAG 的旧故事。候选查找沿用独立的查找轮次，表中只列出它与本状态的交界。
- DAG 的有效性、就绪、复用和批次规则保持不变。审片规则保持不变，唯一例外是「跳过本次审核」：它是对待定结论的放行，绑定其当前硬输入，规则写入 DAG 规范的放行一节。
- 读者 API 路径、Session 类型和模块名、`session_id` 列保持稳定。
- 优先从现有持久数据推导状态。确需新增持久字段时按普通 `drizzle/` 迁移处理，更新 `latestMigration`，并满足上文旧版兼容条件。
- 正式路径与测试使用同一实现。验证使用隔离数据，不触碰读者书库。
- **服务级故障拆分。** 本需求只定义「服务不可用」状态值、显示优先级和出口。按服务共享记录、限流退避、配置恢复后自动解除，以及现有逐篇服务故障的转换另立需求。

## 非目标

- 不用状态机取代 DAG，不改动产物失效规则。DAG 声明与实际读取不一致的问题另立需求，包括：手改画面描述后重新匹配入画人物、重新生成画面描述时清除重绘说明、逐幅结论与条目登记的依赖、全篇叙事结论与幅数核对的依赖、原文核对读取的字段。
- 不新增上文列为「不提供」的入口。
- 不改变界面布局与视觉样式，只修正状态、文案和动作的正确性。
- 不包含未提交改动中的「Letter 双面 PDF」导出。

## 已确认的决定

1. **审核调用失败、没有结论时允许「跳过本次审核」（2026-11-24 确认）。** 规则见验收条件 C017。确定性失败（例如内容被拦截、返回格式错误）时读者仍有出口，与 v0.14.0 一致。接受的代价是未经审核的画面可能被付费绘制，因此限定在暂停、稿件齐备、故障号匹配时，并且要读者明确恢复生成才绘图。没有采用「只提供重试」。
