# 桌面书库备份与恢复

## 问题与决策

拾趣已有 CLI 整库备份、校验和恢复，升级前也会自动保存已校验的快照。桌面控制台只能显示升级备份路径，遇到书库损坏或服务启动失败时，用户仍需找到命令才能判断备份是否可用并恢复书库。

在桌面控制台「本机与存储」的「故事数据目录」旁提供「书库备份与恢复」。用户可以从同一处找到已有备份、手动删除用不到的快照、保存备份到另一块盘，并在服务无法启动时恢复到新目录。

## 验收标准

- [ ] R1. 桌面端展示当前已保存书库的位置及其默认备份目录中的快照。每条显示快照时间、大小和来源（手动、升级前或未知），并可在系统文件管理器中定位。支持从其他目录或外置盘选择快照。没有备份或设备不可用时，明确显示状态及可用操作。
- [ ] R2. 用户可手动备份到默认位置或自选位置，包括外置盘。开始前明确显示来源书库与目标位置。同一书库被桌面、CLI 或开发服务占用时，提示先停服并允许重试。备份成功须经过正式校验，随后显示完成时间和实际路径。
- [ ] R3. 用户可重新校验列表中的快照或外部快照。界面区分快照创建时的校验记录（如有）与本次校验的结果及时间。缺失、损坏或无法访问时，明确指出原因。恢复前须通过完整校验。
- [ ] R4. 服务未启动或因书库问题启动失败时，用户仍能在桌面端校验备份并发起恢复。确认前显示快照、目标路径及兼容性结果（当前版本可打开、恢复副本需要迁移、当前版本无法恢复，或暂无法判断）。旧书库有受支持的升级路径时，使用当前应用迁移恢复副本。涉及降级时提示使用对应的升级前快照与匹配的应用版本。
- [ ] R5. 恢复只写入尚不存在的新目录，校验及所需迁移成功后才报告完成。原书库和源快照继续保留。成功后提供明确的「使用恢复的书库」选项，只有用户确认后才按桌面设置规则切换。服务由用户另行启动。
- [ ] R6. 创建、校验和恢复时显示进行状态。遇到空间不足、占用、损坏、版本不兼容或中断时，明确指出失败或取消的操作及后续可用动作。失败或中断留下的临时数据不能被识别为有效备份或恢复结果。
- [ ] R7. 新旧快照沿用生产 CLI 的格式、校验、占用规则和恢复流程。CLI 生成的快照可由桌面恢复，桌面生成的快照可由 CLI 校验和恢复。升级仍须先保存并验证整库快照。用隔离书库验证恢复后的作品、历史版本、媒体、阅读进度和制作状态。
- [ ] R8. 用户可从备份列表逐条手动删除。确认对话框显示选中快照的时间、实际路径和大小，只有确认后才删除该快照。正在使用的快照、未完成的升级或恢复仍依赖的快照，以及无法确认可安全删除的快照均禁止删除，并显示原因。执行删除前重新确认保护状态，避免与新开始的维护操作冲突。取消或拒绝时保留快照，成功后刷新列表。
- [ ] R9. 在支持书库格式 V2 的桌面应用中选择已校验的 V1 备份，确认前提示恢复副本需要执行迁移 `0025_production_dag.sql`。恢复流程只在新目录的暂存副本上运行迁移，校验通过后提交为新的 V2 书库。用隔离书库验证新库可由 V2 应用打开，原备份仍为 V1 且全部文件哈希与恢复前一致，并能用匹配的 V1 应用恢复到另一新目录并打开。迁移失败时原 V1 备份仍可用于回退，目标路径不出现可选用的书库。

## 范围

备份为私有整库快照，界面明确说明全局设置和存有 API 密钥的 `desktop.sqlite` 在范围之外。维护操作仅在本机执行，无需启动 HTTP 服务或调用模型。产品文案应说明，同盘的升级快照用于回退，单独设备上的副本可用于硬盘故障后的恢复。

快照仅通过用户确认的手动操作删除。定时备份、云同步、加密归档和书库合并留待后续。第一版由桌面控制台提供操作入口，网页「我的」里的跳转可按需另议。

无待确认的产品决策。
