# 按需全文／章回选题实施计划

原故事Git base：`a7c1943ad5d94421c1812af630cacdc72c2a27b1`；旧实现里程碑`f02020a`保留。替换实施基线：`ab8e0d20194b7f0f22ba3e71976449828cc68a37`。本轮用户已撤销暂停并授权替换候选库，旧AR/CR结论不适用于新设计。入口其他聊天的README和Reader界面改动、StoryEndingSurface等不属于本任务，不覆盖、不混入提交。

## 设计

1. 增加服务器本地tiktoken依赖和token预算模块。完整请求（提示词、JSON payload、schema）采用o200k_base估算，Codex整本输入预算400,000 tokens（相对默认500,000留100,000）；Gemini先以UTF-8字节上界做保守规划，不能把OpenAI分词数当Gemini精确计数。按用户补充要求，增加pnpm run library:prepare，无需模型调用预先划分24本书，小书统一为一块。把分块清单（起止范围、token数、版本）单独原子缓存，各主题共享，载入时核对完整覆盖且不重叠；不重复存原文。清单身份包含原文、规则、预算、提供方，和主题/已看列表无关。超预算按连续章回组合到约50,000 token，单章过长按原文单元再切；剩余提示词／未完事件原文始终在完整请求预算内。
2. 取代story-index与candidate-summary合同。模型直接接收主题、已选出处、未完事件及本块和未完事件对应的真实原文，返回≤5个完整故事、显式blockComplete、resolvedEventIds和≤16项有来源的pendingEvents。现有输出5篇上限不变。返回满5篇时保留当前块，下次带排除出处继续；返回不足且明确完成、所有结果合法时才推进。无进展、无效／重复结果不推进，不用短响应长度推断耗尽。
3. 旧单章出处保持有效，增加有序、不重叠的continuations范围。LocalBooks统一校验版次、各范围、异常字与来源长度预算，拼装带章名的完整原文，提供统一sourceKey／重叠判定，分镜之前重新校验。世说仍只允许单则。移除12000字符任意截断，保留足够且明确的token上界，绝不裁切原文以凑预算。
4. 新命名空间与旧候选库彻底隔离，身份覆盖书、版次、解析文本、规则/schema、输入预算、提供方/模型，主题单独NFKC+trim。每主题仅保存stories/cursor/pendingEvents/exhausted，缓存载入重新验证。已有故事池与调用者已看列表分离，按来源重叠过滤；并发先共享扩充再分别过滤，不足再扩充。每次模型成功先原子保存，再检查取消/是否凑够5篇；读取/写入故障明确失败。
5. 未完事件使用服务端生成的稳定ID（首次由出处/题目散列），更新必须引用既有ID；新事件ID为空由服务端赋值。未被模型返回的旧事件继续保留，不能因遗漏而删除。更新累积原有和新增的原文范围，不能丢弃旧证据；resolvedEventIds只能在本次已通过校验的完整故事覆盖对应事件的全部证据时消费。重复/伪造ID、合并后超过16项或范围/预算超限均安全失败，保留原cursor/pending。未完事件携带真实来源原文进入后续章回。来源必须在当前块或已验证pending原文中；不得引用未提供的章节。未完上下文或排除列表使完整请求超预算则明确失败并保留进度，不静默删除。所有章回结束仍未完者不当作完整故事返回。跨章故事可由多个不连续范围组成。
6. HTTP请求增加已看出处列表，保留旧标题排除兼容；客户端历史版本更新，source按结构比较而非仅四个旧字段，来源请求／会话body上界相应调整且保持有界。页面不展示候选库，明确本次选题／已扫描字数，达到5篇即可在未读完整书时返回；整本调用中只显示等待，不伪造百分比。沿用210秒流空闲超时和120秒普通选题上限，真实53秒实验支持该上限。
