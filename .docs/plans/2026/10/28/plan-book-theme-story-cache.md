# 全书索引与主题故事缓存实施计划

Git base: `a7c1943ad5d94421c1812af630cacdc72c2a27b1`。入口已有未提交的加载、字数进度与取消代码是本任务的衔接基础；其他文档、原文整理及 reader-request 改动不属于本任务。保留并发工作。

## 方案

1. 本地书库已合并原文，不能仅把超长正文拼成更大的请求来消除模型工作。按现有有界输入通读，但索引阶段不接收主题、画风、制作要求或排除标题；索引输入按最多 40,000 字符的独立预算重新分批（原有通读输入保持 100,000 上界不变）；每批提取至多 12 个可核对故事候选，输出简体标题、情节梗概和稳定来源。合并时按原文范围去重。候选索引不承诺穷举全部故事。
2. 复用 FileMedia 的原子写入和路径检查，在运行数据 media/reader-cache 下保存批次、全书索引、主题候选结果。JSON 格式独立版本。索引命名空间包含书籍 ID、edition、带编号的正文 SHA、有效索引提示词/输出结构版本和提供方/文本模型身份；主题缓存另加入当前合并索引摘要、有效主题提示词和主题输出结构，主题展示规则改变只使主题结果失效，不重建昂贵索引。主题仅做 NFKC 与首尾空白规范化，不混并不同含义。
3. 所有缓存载入后做结构验证和本地出处核对。损坏缓存视为未命中；无法读取/写入缓存目录返回安全错误，不伪称保存成功。索引批次先保存再报告完成，即使取消也保留已完成工作。
4. 同书同版本首次构建共享单个任务，主题选择另按主题共享任务；等待者收到当前字数进度。等待者独立取消，全部取消时中止后续派发；已经发出的模型请求完成后保存当前批次。新请求等待被取消任务收尾后再从检查点恢复，避免重复派发。
5. 首先筛出主题缓存中未排除的故事，够五篇或已标记当前索引候选耗尽时直接返回。不足时只从全书索引中排除已知标题与出处后，调用 candidate-summary 模式补选。每次候选输入 JSON 最多 30,000 字符；超限时按顺序分组全部候选，每组至多选五篇，再递归有界合并，所有组（包括尾部）均参与，不能截断候选或重读正文。每一层只接受该层输入已有的精确来源。共享任务扩充主题缓存池，返回后仍按每个请求自己的排除列表过滤；不足时再合并扩充任务。异常或不完整输出不标记耗尽；有效完整选择少于五篇才视为当前索引没有更多匹配。合并并保存主题结果，再返回至多五篇。
6. 两种提供方增加 story-index 用途与最多 12 篇的有界输出结构，Gemini 索引输出预算 8,000 tokens；真实16批运行中单批120秒超时，调整仅索引任务上限180秒，普通选题、分镜和图片仍保持原时限。客户端无进度超时同步210秒（覆盖180秒索引等待及状态/存储余量）；选题/最终 API 保持五篇上限。索引实际 payload 不包含主题、制作要求、画风、排除列表。缓存身份来自 status 的提供方和配置文本模型；Codex 只读 config/read 暴露配置模型，仍为缺省标识时不宣称能检测供应商静默升级。短书也先建索引再筛主题。

## 风险与决策

- 索引一开始仍需通读；比重复读取省的是后续请求。每批最多 12 个候选，若模型输出不完整则失败，不缓存不完整输出为完成。
- 本应用是单 Node 服务/本地单 owner；不承诺多个进程同时写同一运行目录的模型任务去重。
- 缓存只保存已核对来源。缓存失效不删除阅读会话或已生成内容；新命名空间可安全重建。
- 真实请求可能遇到模型超时或源代码重载；先定位实际失败，再决定有依据的调整，不放宽出处验证。
