# 《搜神记》全书事件卡与雨类检索 PLAN

[需求](../../../../reqs/2026/11/07/req-hybrid-story-extraction.md) · [验证方案](../../../../tests/test-hybrid-story-extraction.md)

在 `codex/soushen-semantic-search` 的独立 worktree 继续。Git 基点 `ccfe74a`，另有 REQ 所记录的事件卡与 CLI 工作树改动。现有试点已接通离线混合检索、原文提取和 `books search <查询> [书名]`。已知快照有 463 条范围、4 篇事件卡及 109 条查询向量。执行前以冻结快照中的实际记录重新核对这些数量。

## 一、《搜神记》全书制卡

- [ ] 用 SQLite 一致性备份冻结当前运行索引，另外记录制备库的版本、条目数、阻拦原因、模型摘要和事件卡覆盖。以现有切分为本轮基线，保持故事范围与已有原文向量可比。制备只使用实验目录的 `.data/soushen-search.sqlite`，候选运行快照先单独保留，整个过程不访问正式 `shiqu.sqlite`。
- [ ] 全量前从不同卷挑一小批可用条目，含长短文本、普通叙事和已知难例。先用 `events <条目编号…>` 记录每篇用时、产出、空卡和失败原因，再中断一次并重跑，确认同模型和同契约的已校验卡可复用，失败项仍可追踪。默认千问与 Codex 审校卡的指纹不同。先确认如何保留同版且有证据的已审校卡，或在全量后从冻结快照恢复并复核这些条目，避免重做时丢失审校。用谈生的复生未遂作为保留检查。根据实际吞吐安排批次。若证据编号或续跑不能稳定核对，先修复该问题，再启动全量。
- [ ] 复用 `scripts/experiment-soushen-search.mjs events` 为全部可用条目生成事件卡。优先使用千问。对失败项先按错误原因分批重试，对古文语义难例再按条目启用审校，记录采用的模型和结果。保存每轮报告，并将非空有效卡、核对后确实无可记录事件、原文阻拦和待处理失败分开统计。每个非空事件保留角色、行动、对象、目的、结果或状态及可核对证据。
- [ ] 只有可用条目全部有有效事件卡或已核对的空卡、且待处理失败清零，才标记全书制卡完成。核对事件向量、原文范围与版次，执行 SQLite 完整性及外键检查。用 `refs` 生成同模型的参考表，显式保留本轮查询组与已有回归词。记录参考表大小和制备成本，将新快照复制到单独验证目录，供 CLI 和应用读取。

## 二、验证求雨、下雨和止雨

- [ ] 在查看新索引排名前，冻结一份按原文标注的测试集。每条记录出处、实际事实与相关查询，允许同一篇同时满足多个查询。覆盖求雨成功、求雨未遂、自然下雨、自然雨停、主动尝试止雨，以及水势平息但原文没有记载止雨等容易混淆的情况。若书中没有核到主动止雨的正例，记录查找范围和证据，把该组标为仅能核验误召回与误提取。可用一个明确标为合成的原文样本验证正向路径，单列结果。
- [ ] 对旧事件覆盖和全书事件覆盖使用同一版原文、同一查询组、相同候选上限，并从同一份制备结果复制测试查询向量。对照两份索引中每个测试键的原始查询、模型摘要和向量哈希，防止新增事件词覆盖同键查询。比较 `pnpm cli books search` 的前 14 和前 42 候选，逐组报告已确认正例进入数量、排名和典型混淆项。对漏召回或排名靠后的条目，记录原因属于切分、事件卡、文字匹配、向量或融合中的哪一环。控制查询包括「求雨成功」「雨停了」「雨」和「险些复生」。
- [ ] 用应用现有提取入口分别运行「求雨」「下雨」「止雨」，并在含易混负例的有限章节核对拒绝行为。两份索引的每条查询各用新建的临时应用数据目录与空缓存，使用同一个提取模型和设置，最多三轮或两分钟，以先到者为准。逐条记录原文依据及路径，区分索引候选、已有目录和顺序阅读。若走了顺序阅读，记录实际覆盖与是否读完。预算内未完成的查询记为未判定，无法作为全书无结果的证据。
- [ ] 验收以冻结样本为准。每组有真实正例时，已约定的关键正例须进入前 42，并能经正式入口从索引候选提取到符合条件的故事。最终提取不得把未降雨的祈求当成「下雨」，也不得把自然雨停或水势平息当成「止雨」。候选误召回单列分析。若不达标，先处理共同原因，再用冻结样本和新选的对照样本复测。达标后才将已验证快照装到试点运行目录，保留可回退的上一份快照。

## 三、评估扩到书库

- [ ] 完成前两阶段后，根据覆盖率、真实三类验证状态、制备速度、人工审校比例、索引体积和查询成本，决定是否继续。主动止雨若仍缺真实正向证据，决策中明确该限制。
- [ ] 若证据支持继续，先写统一索引的后续方案。按书籍与版本管理来源、向量及更新批次，共享同模型的查询参考表，验证按书筛选、全库搜索、单书重建和旧索引兼容。下一轮只选一本版式不同的书做增量试点，本轮到决策为止。
