# 故事卡实时向量检索

Git 基点：`e7b32cb`（`main`）。进入时唯一未跟踪文件是本故事 REQ，属故事输入。该改动横跨用户设置、书库备份、Ollama 网络调用和读者检索流程，按非低风险处理。

## 结果与边界

- 保留一个用户书库级故事卡向量 SQLite 文件，放在书库备份范围内；按书、原文版次和卡片指纹识别有效记录。当前原文与来源仍由 `LocalBooks` 校验。
- 从现有内置轻量故事卡和可验证来源的本地卡生成标题+白话梗概向量。一个故事出处一条向量；重建同一书/版次幂等替换。构建按书单独执行、可取消、重试且报告进度/原因，不在后台扫描全库。
- 通过服务器代理访问用户配置的本地 Ollama。身份记录模型名、Ollama 返回的模型指纹/版本、维度和固定输入编码规则。查询向量仅与全部身份字段相同的索引比较；切换模型立即使旧向量失效，文字召回继续工作。
- “我的”提供 Ollama 地址、模型选择、连接测试、启停和书籍覆盖/构建状态；不修改现有生成及原文核对模型设置。备份只包含用户向量库，不含 Ollama 缓存或应用级官方资源。
- 同一选书页提供章节、故事、主题入口。章节目录与原文不依赖向量；故事优先精确标题/别名，再做卡片文字检索与实时语义补充；主题合并卡片、原文文字和兼容向量候选，范围过滤、出处去重、上限 50，然后复用生产文本模型核对排序。模型不可用时展示标明未核对的候选。
- 无模型命中/主题未命中时可按选定范围继续分批查原文，复用已有提取与读取进度，显示进度及“已检查完整范围”状态，支持取消。不得把候选未命中表述为全范围未命中。
- 停止读取官方向量包和预制查询向量；保留安装在磁盘上的旧包和用户导入文件，但新召回不得访问其向量。若继续支持 `books index-import`，它只用于可重建卡片元数据/词检索，并同步 CLI 帮助、内置技能和示例。
- 用静态可点击桌面/手机原型先走通首次使用任务，后按同一导航与状态实现正式界面。

## 关键决定

- Ollama URL 可由用户设置，默认 `http://127.0.0.1:11434`；服务端限制为本机/明确本地主机地址，错误不暴露凭据或原始响应。Docker 的宿主机访问路径需通过有界可配置地址支持并以隔离探针确认，不能假定容器 localhost 等于宿主机。
- 可行性探针结果：宿主机 Ollama `/api/tags`、`/api/show` 和 `/api/embed` 均正常，`qwen3-embedding:0.6b` 返回 1024 维向量；本工作区 Docker daemon 未运行，`host.docker.internal` 当前无法解析。因此实现不硬编码容器地址；Docker 部署的主机连通性保留为明确验证限制，不能据此宣称已覆盖。
- 索引是可再生成的缓存，模型标识以 `/api/show` 返回的模型身份及模型清单可观察版本为准；任何无法确认的版本变化均要求重建，不凭维度推断兼容。
- 实际 Ollama 连接/模型探测是 SS 的首个有界可行性探针。没有本机 Ollama 时，先完成基于 mock 的同一生产请求路径；该限制将影响真实模型相关验收，须记录而不可伪称通过。
- 只在书库就绪后访问或修改书库，沿用现有备份校验、原文版次校验和故事出处 schema。新增可恢复数据无需迁移核心 `shiqu.sqlite`。
