# 计划：收窄制作 DAG 的范围，界面以 v0.14.0 为基线

状态：已按评审修订，U1–U6、默认还原无关界面改动、`--cover` 恢复均已确认；实施中（阶段 0）。依据：[规范](../../../story-production-dag.md)、[实施计划](../21/plan-data-driven-production-dag.md)、[交接](handoff-production-dag-cutover.md)。

## 1. 目标

读者对 v0.14.0 的核心不满是**失控**：故事开始后一旦修改，不清楚该重做什么，容易漏做或重复付费。保留 DAG 只为证明三件事，并且**通过现有编辑器**证明：

1. 修改之后恰好重做依赖它的部分，不漏、不重复；
2. 故障只阻断依赖它的工作；
3. 有一张由登记表生成的流程图，以后加步骤改登记表即可。

不做：为 DAG 增加新的读者功能；让新建作品的成本超出 §5 的门槛；在没有真实数据验证前合并。

## 2. 基线与界面约束

- **界面基线 = `aad2aac`（切换开始前的 main，DAG 之前的最后一个提交）；`v0.14.0` 只作发布对等关口（升级、回滚、命令行与核心流程对等）的参照。**
  - 审计结果：`v0.14.0` 到 `aad2aac` 之间有 30 个 main 提交（含 `ff0f3c7` 「Streamline story production edit submissions」、分镜批量编辑、重选恢复等），这些已经改了 15 个客户端文件，**不是 DAG 分支做的**。DAG 分支相对 `aad2aac` 只改了 **2 个**客户端文件：`StoryGenerationControl.tsx`（「继续制作」、「应用当前模型设置」）与 `useStoryRevision.ts`（服务端预估）。
  - 因此「还原无关界面改动」的范围只有这两个文件，且其中的改动都属于 U1/U4/U5；以 `v0.14.0` 为基线去还原，会误删 main 上 30 个提交的正当改动，不做。
  - 之后每个新的客户端改动同样逐处核对，必须属于 U1–U6 或为渲染同样界面所必需的内部适配。

### 已批准的可见变化（逐项批准，其余为零）

| 编号 | 变化 | 性质 |

### 命令行对等（独立的合并关口）

命令行相对 v0.14.0 不得丢失输入：首幅原图（`--cover`）目前对 DAG 故事被拒绝，**切换前必须恢复**（不涉及界面）。沿用 v0.14.0 的回归测试，验收：所给图片字节不变地保存；优先于已加星标的书籍参考图；请求重放时复用同一张；「继续制作」之后只绘制其余画幅。`stories continue` 是对应 U1 的新命令；`edit` 不要求 `paused`。`skills/shiqu/SKILL.md` 与帮助同步。

## 3. 手改：默认保护，不弹窗

- 能保留的手改一律保留。
- **修复保护标记**：当前「以手改为基础」会清除 `handEdited`，之后的再次失效就无法保护；修订后手改标记必须保持，直到读者自己改回。
- 若这次修改会使重新编排丢掉手改（例如制作要求改变导致整体重编排）：**不保存**，保留编辑草稿，在现有编辑器内联提示「这次修改会重新编排并丢弃第 N 幅的手改，请先撤销该设置修改」。读者仍可通过 API 的 `handEdits:{id:'discard'}` 显式放弃（命令行可用），界面不暴露。
- 不再默默放弃任何手改。

## 3a. 故障延续按输入判断

修订保存时，上一版待处理的故障只在**该故障涉及的节点输入没有变化**时带入新版；输入已变的故障不带入，新内容重新开始。判断对象是故障任务所覆盖的全部实例（批量任务按其记录的实例，而不是整个故事级别一律带入）。必须有的用例：

- 提纲失败后，读者改了制作要求 → 新版不带入该故障，「继续制作」后新提纲运行；
- 未变化的图片失败 → 新版仍带入，须读者明确重试，「继续制作」不会绕过。

## 4. 预估与保存使用同一计算

当前预估缺少审核意见的变化，对保存会拒绝的手改选择了默认值，并回退到旧的客户端估算，这违背保留 DAG 的初衷。修订：

1. 抽出**一个**修订计算（输入：当前版、变更；输出：新版 dag、保留的故障、手改后果、需要重做的工作），保存与预估都调用它；预估只是不写入。
2. 预估包含审核意见变化、手改保护与冲突（冲突时预估返回冲突说明，而不是替读者选择）。
3. 客户端无预估时显示「预估暂不可用」，删除对 `revisionImpact` 的使用。
4. 测试：预估与保存都**不触发任何模型调用**；对同一变更，预估与保存得到相同的重做集合；「继续制作」只执行受影响的工作（按调用计数断言）。

## 5. 成本探测（先于任何界面工作）

分别比较 v0.14.0 与本分支，**新建作品**与**代表性修订**分开，文字调用与绘图调用分开计数：

- 新建：同一批 3–5 个故事；
- 修订：只改一幅配文；校正首幅；改制作要求；换画风。

比较条件：同样的故事、模型与设置，产出质量可比；文字调用、绘图调用与耗时**分别**记录。

门槛：
- 新建：总调用与费用不超过 v0.14.0 的约 1.3 倍（暂定上限）；
- 修订：DAG 承诺节省的场景须有明显节省，尤其是**校正首幅**；只改一幅配文在 v0.14.0 已是零次绘图，持平即通过；
- 若新建更贵，检查修订的节省按你实际的工作比例能否抵消这笔溢价；
- 验收条目登记：**冻结，先量成本**；若其成本显著，在发布前简化（见 §6）。

### 升级与手改的识别范围

转换把旧内容原样保留但标为旧规则（`legacy`）。升级后新的手改保护**只能可靠识别升级之后的手改**：升级前的文字没有「读者手改」与「模型生成」的区分记录，转换器把它们都当作已有产物。因此：升级前的编辑在升级后按普通产物处理，会被依赖它的上游变化按引擎规则重新生成；升级演练要明确记录这一点，并在发布说明中告知。若需要保护升级前的手改，必须有旧版对应的编辑记录（例如修订记录里的 `plan` 差异）作为依据，否则不承诺。
