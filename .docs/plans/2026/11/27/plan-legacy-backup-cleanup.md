# 清理无法使用的旧书库备份

Git 基线为 `2ca9d69138809e66cac1800eab821af2b73dbcaa`，工作在独立分支。目标见 [需求](../../../../reqs/2026/11/27/req-legacy-backup-cleanup.md)。

- [x] 复用备份目录验证、锁、回退引用检查和一次确认。只有位于当前书库规范备份目录、目录名符合自动升级快照格式、且存在拾趣清单文件的快照，才允许走缺少归属记录的检查分支。损坏的清单内容仍可显示为不可校验。归属记录存在但无法信任时继续拦截。核对规范根，并检查相邻指向同一备份根的旧别名；保护该书库的正式回退报告。历史上随意建立且不在目录中的外部别名不可枚举，需要操作者知道它是否属于另一本书库。
- [x] 列表标明缺少归属，确认框显示所选路径和额外风险。服务在锁内重新判断保护和确认类型，并核对目前的快照身份。删除令牌绑定当前规范书库以及归属状态，不能复用原来的确认。桌面使用实际可见的确认框。
- [x] 用隔离样本验证缺归属的可清理快照、损坏快照、后续新增的回退依赖、回退报告、共享根别名、正在使用、归属双向切换导致的过期确认和取消。测试过程不读取或修改真实书库。
- [x] 更新使用指南，运行相关测试与代码检查。

删除只应用于用户确认的一个明确目标，行为变更不涉及数据库和备份格式迁移。旧入口继续保留锁与回退保护。
