# 桌面复用书库服务

桌面点击「启动服务」会先连接同库、同版的持锁 Node 服务。已有 CLI 浏览器服务沿用原 PID、地址和配置。短时进程先处理完已接收的命令，再在原进程启用阅读器。两种 CLI 用法共享书库所有权和本机控制，短时命令只在桌面请求启用阅读器时转为常驻。

私有 `/lifecycle` 在同一经过认证的回环端点处理接入、状态、停止和强停。`/command` 处理书库请求。桌面 stdin 转发进程只负责控制。正常停服有确认回执，最终状态以持锁服务实际结束为准；意外断开桌面连接保留已有服务。校验期间停服保留故事原授权，强停先取消模型请求。

## 验收

`VR passed: all acceptance criteria complete`

1. 通过真实 CLI 浏览器入口启动，桌面使用原 PID 和 URL，原阅读器读到 CLI 新建的作品。IPv6 回环也通过。
2. 已领取的临时 CLI 命令正常返回，原工作进程与命令地址不变，并在超过原空闲期限后继续提供阅读器。接入取消或端口被占用时恢复原临时行为。
3. 桌面 stdin 验证连接断开、常规停止、重启、立即停止和服务异常退出。用受控模型请求核实常规停止等候，强停取消，异常退出不显示为成功。原生检查继续回归退出状态和服务关闭确认。
4. 错误版本被拒绝；陌生监听者只收到身份探测；另一书库使用独立持锁者。同库激活只在通过认证后提交桌面配置。
5. 有等待的故事在派发前中断后继续等待，浏览器已授权故事在同一条件下重启后完成；已开始的全量 CLI 制作继续，有限任务保留停点。
