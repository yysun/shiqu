# 通过 SKILL 使用拾趣：提示词示例

技能通过拾趣 CLI（桌面内置入口或 NPX）复用桌面与 `pnpm dev` 使用的共享设置数据库：提供方、对应密钥、模型和任务推理档位只需保存一次。发布包安装的技能默认通过 `npx --yes @apprun/shiqu@<技能版本>` 调用 CLI，需要 Node 24 和随附的 npm/npx，无需 pnpm；源码入口使用 `pnpm cli`。用户明确指定其他启动器时沿用其选择。技能安装只复制指引与版本记录，不全局安装 shiqu 命令；检查或更新后沿用匹配的固定版本。

显式 shell 变量优先且只影响本次运行，CLI 和开发后端均不自动读取项目 `.env`。技能自身不保存另一套生成配置或密钥。修改设置后，运行服务的新生产步骤和下一次 CLI 执行会读取新配置；同一书库的 CLI 操作需先停止占用它的服务。

## 启动自动安装与桌面 CLI

使用包含此功能的版本时，普通 NPX 服务或桌面「启动服务」成功后会准备用户级技能。缺失时安装；已有副本仅按原 `auto-update` 同意同步随包版本，保留定制、未知来源和较新副本。启动不查询 npm、不下载新版本、不修改宿主配置；技能被停用或已有启用的拾趣插件时跳过，安装失败也不阻止服务。帮助、配置、维护和其他独立命令不触发安装。

```bash
npx @apprun/shiqu skill auto-install
npx @apprun/shiqu skill auto-install off
npx @apprun/shiqu skill auto-install on
```

`SHIQU_SKILL_AUTO_INSTALL=off` 只跳过本次启动；自动安装开关不改变 `skill check --auto-update on|off` 的更新同意，也不删除已有技能。

桌面包同时携带生产 CLI；安装时在技能目录登记受哈希保护的 `.shiqu-runtime.json`。助手核对版本与哈希后，以参数数组调用绝对 Node/CLI 路径，无需系统 Node/npm/npx。桌面被移动后，重新启动服务可更新受管路径；失效或被修改的记录会被保留并报告，不静默安装运行环境。没有系统 npm 时，通过更新桌面应用并按原更新同意在下次启动同步技能。

这里仍是直接开库的 CLI：操作同一书库前需安全停止占用服务，不能绕过锁，也没有 `--url` 模式。技能管理命令不访问书库，不要求停服。

## 安装技能

### 在所有项目中使用

```text
请为我全局安装拾趣技能，让我可以在各个项目中使用。
技能来源：https://github.com/yysun/shiqu/tree/main/skills/shiqu
如果已经安装，先比较现有内容；有差异时先说明，不直接覆盖我修改过的指引。
只完成安装，不创建书库、不配置生成服务、不开始制作。
```

### 仅在当前项目使用

```text
请把拾趣技能安装到当前项目，仅供这个项目使用。
技能来源：https://github.com/yysun/shiqu/tree/main/skills/shiqu
保留项目中已有的其他技能，不修改全局配置，也不开始生成故事。
```

```text

```

### 单次升级

```text
$shiqu 把当前项目使用的拾趣技能更新到最新正式版，之后用配套版本继续工作。
保留本地修改；如果无法确认现有指引来自哪个版本，先说明差异，不直接覆盖。
这次更新不代表允许以后自动升级。
```
