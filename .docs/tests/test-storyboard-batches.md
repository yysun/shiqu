# Storyboard batches verification

1. 固定 45 幅故事，从已核原文开始请求制作。观察保存提纲，随后批次为 1–20、21–40、41–45，最后才开始绘图；API 进度已保存数依次为 0、20、40、45。
2. 第二批失败，重复读取不发起付费调用；重试只生成第二批，保留提纲和第一批，畸形或不足数量的输出不追加。
3. 第一批完成后暂停或停止，后续批次不启动；重启服务并恢复，复用提纲与第一批。
4. 两个并发窗口请求同一批，只执行一次付费调用。
5. 1、20 幅保持一次完整编排；21、40、60 幅正确收尾；自动幅数由提纲确定且最终幅数一致。两提供方具有相同调用结构和衔接资料。
6. 使用桌面 Vite 预览与 in-app browser 查看生成进度；已保存 20 / 45 幅时显示当前范围和保存数量，未完成前无绘图或模型百分比。
7. 80 幅分为 20/20/20/20，后台生成覆盖第 80 幅；第 80 幅媒体、阅读记录、事件可用，81 幅与第 81 幅访问遭拒。

优先以可控提供方和真实 SQLite/HTTP 验证；不发起真实付费生成。
