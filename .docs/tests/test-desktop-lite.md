# Desktop editions E2E

Use a packaged macOS app and disposable data/config directory where possible. Do not use a real API key or request paid generation. Record actual evidence and platform limits in the plan.

1. Launch Standard with system Node absent from PATH and any saved custom Node path invalid. The settings report bundled Node 24.22.1/SQLite and the server starts. A missing/corrupted bundled executable reports a reinstall error and never selects system Node. Standard hides system-runtime selection. Build Lite with the override: it excludes Node and retains its existing missing/Node 22 rejection and explicit Node 24.22.1 selection behavior.
2. Configure a disposable data directory and Gemini with no key. Save, quit, relaunch: nonsecret settings persist and the sample remains readable. Enter a disposable test key, reveal/mask it, save, then quit/relaunch and confirm only the saved-presence indicator returns. Delete and confirm the database record stays absent after relaunch without launch environment. Inspect the private native database: the selected key is persisted as disclosed plaintext, while settings responses/payloads/logs/reader routes contain no key. No session-only control exists. A provider test without a key reports a safe local error and makes no request.
3. Start with phone access disabled. Status becomes Running, Open in browser launches the plain localhost origin, the browser reaches the reader directly, and no LAN URL/QR is shown. Cookie-free requests to stories/media succeed.
4. Stop, enable phone sharing, restart. Show actual LAN URL(s) and scannable QR. Open one direct IP/port link in the in-app browser (a separate simulated phone client when physical device unavailable), read the sample, write reading progress, restart/reload, and verify persisted progress. Direct access still works after restart; foreign Origin/Host requests fail. No settings/key endpoint exists.
5. Stop the server and verify listener closes. Occupy the configured port and start: show a bounded actionable error and recover when the port is freed. Close the window: tray/background operation remains. Open another app instance: focus the original. Quit: server exits and listener closes, including on parent-input EOF/crash. Duplicate desktop data-directory lock is rejected.
6. Inspect packaged resources outside the checkout: all dependencies/books exist with no `.env`, API keys, personal data, developer symlinks, or dependency-install step. Standard includes matching Node 24.22.1, license notices and checksum/provenance metadata; copy it with the runtime and run using only the bundled executable and an empty/unusable system Node PATH. Lite excludes Node. Run `pnpm start` separately and confirm the ordinary reader/API still work.

The LAN direct-access browser check is not evidence of physical phone scanning or firewall traversal. macOS E2E is not Windows/Linux runtime verification. Document these limits.

7. Fresh database: legacy settings.json imports once; alter settings in SQLite then relaunch with stale JSON still present and confirm database wins. Invalid/corrupt/future schema fails safely without overwriting original bytes. Failed settings/key save rolls back both. Check Unix directory/file permissions; no native database is in the packaged resources or reader routes.
8. Using only synthetic environment values, verify first launch imports GEMINI_API_KEY only when the database has no key, saves it for later launches without the environment, and never overrides an existing saved key. Delete in the running app and confirm no repeated import; a new app launch may import again. Invalid values report a value-free warning while settings remain usable for valid input. Confirm no shell execution and child environment excludes API secrets. No actual provider request is made.
