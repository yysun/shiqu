# 提示词清理验收场景

1. **阶段与提供方契约**：受控 Codex/Gemini/OpenAI transport 记录实际请求。分别调用选题、幅数、提纲、分批与整篇分镜、标题结语、审核、修订、绘图构建器。核对阶段任务单一、输出和 schema 一致、字段仍为数据、主题隔离、画风和用户要求传递不变；不实际绘图。
2. **兼容输入**：使用重构前的冻结指纹和旧自动预设。读取 v2 选题缓存、加载已保存原文/分镜；旧默认要求归一化，用户自写要求逐字保留；不重写现有书库。
3. **复杂故事文字对比**：相同原文、选题和模型/档位下，对比重构前后自动幅数/提纲，并审核已知截断的连环计 18 幅。检查起因、关键选择、决定性行动、原文结果和开场；截断稿必须要求重编，不直接绘图。
4. **短篇与对白**：使用短小独立故事和长对白/比喻文本，对比配文可读性、说话归属、条件/对象、关键反应与画面变化；不得靠凑幅或心理解说弥补理解。
5. **边界与误报**：原作开放结尾或明确指定片段，允许其自然结束，不要求补造结果；结语可以凝练抽象，不以未点名人物而误报；全篇结构缺失仍与局部文字问题分开。
6. **已有流程**：全量本地测试验证审片/修订/重编/绘图闸门和缓存、原文、版本、只读模式保持正确；类型检查和 lint 通过。

真实文字证据放入忽略目录 outputs，记录模型、推理档位、输入/提示词摘要哈希、请求阶段、结果、耗时与人工判读。失效、超时和不可访问情况原样记录；不以测试桩冒充真实模型评测，不把代码声明当成成图验证。
