# CLI 共享书库与桌面单版验证

1. 临时用户目录无配置、无库：非交互启动失败并提示 --data-dir，不产生库；终端确认建议目录后创建 SQLite，重启复用确认路径。取消/EOF 不产生配置或库。
2. 临时桌面设置只含 desktop_settings：保存目录不存在，CLI 不询问并创建；放入真实故事/图片/阅读进度后，在相同版本桌面服务打开可读。反向桌面写入后 CLI 可读。凭据表不需要读取。
3. 桌面保存目录和显式 --data-dir/SHIQU_DATA_DIR 冲突：显式选择生效，相对路径按调用目录解析。桌面配置损坏明确报错，显式目录可绕过；--help/--version 无副作用。
4. 已有 CLI 独立库：不删除、不合并；使用 --data-dir 可继续读取。没有桌面配置但默认桌面目录已有 shiqu.sqlite 时直接复用。
5. 两个 CLI 或 CLI/桌面尝试同一库：仅一个成功。正常停止、端口占用及启动配置失败后占用释放，随后可重启；陈旧占用回收不能让并发新实例同时成功。所有数据使用临时目录，无真实 AI 请求。
6. 静态检查 Lite 构建命令、override、UI 选项、发布分支移除。桌面必须始终使用内置 Node，旧 nodePath 不影响运行时。CI 仅上传并校验两平台原 standard 命名安装包。README 及指南的本地链接有效。

JS/SQLite/HTTP 使用项目测试与独立临时进程；交互用 PTY 或注入交互输入验证。只做本地检查，不执行桌面准备/构建、Docker 构建或发布。
