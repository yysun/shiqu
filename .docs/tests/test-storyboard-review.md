# Storyboard review verification

1. 新故事完成目录和批次后独立进入全篇审片；审片在途/报错/发现问题时不启动任何图像请求，空 issues 才放行。短故事同样审片。
2. 审片指定相隔及相邻幅号，修订请求只包含对应编号；未指定页、全篇元数据、目录和总幅数不变。21 个问题分为 20+1 两批，随后复核，跨批边界也接受全篇上下文检查。
3. 审片重复/越界幅号、修订缺页/重复页/多页/坏字段都失败且不追加，不绕过绘图门槛；重试复用已保存目录、分镜和审核报告。
4. 一轮修订后复核仍有实质问题，停止自动生成并显示问题幅号；两个客户端均不自动付费重试。手动继续后只修订已知问题并复核。
5. 审片或修订中暂停/停止/失去阅读需求，保存当前付费结果后停止后续步骤；重启只续未完成任务。并发窗口或已保存检查点的旧队列回执重放不重复付费步骤。
6. Gemini/Codex 实际适配器通过受控模型收到一致审核维度与修订上下文；本地原文验证覆盖新入口；旧完整 plan 无审片标记时直接沿原流程继续。
7. 进度区展示审核/修订及未通过状态，手动继续文案明确；只有审核通过后图像阶段为 current。使用实际 React 组件静态渲染验证文案与标记；浏览器可用时补 in-app 验证。

使用受控生成与临时 SQLite/媒体目录；不修改既有故事，不调用真实推理或图像生成。没有重新测量实际耗时或宣称艺术质量已通过实图验证。
