# 按需全文／章回选题与缓存：可执行流程

1. 独立空数据目录，真实Codex订阅，通过当前应用API选《阅微草堂笔记》／给我一个反转。预期：直接发送全文，不建候选库；120秒内至多5篇，本地出处均可核对。保存实际耗时和流事件。
2. 相同目录重复同书同主题：返回相同故事池、缓存提示，新增模型调用为0；重启服务后同样成立。
3. 排除第一批的标题和原文出处，换一批：不重复旧来源、不通过改名重复；整本模式允许再次发送全文，模型次数留证据。
4. 超大分块确定性集成：第一个块返回5篇便停止；换批先继续同块，明确完成才读下一块。一个事件在第1章未完，中间章遗漏返回仍保留，后章按稳定ID补充原文，完整故事覆盖证据后才消费；伪造事件ID、无完整故事却声称resolved、超16项不能推进。第2章返回跨章来源；原文核对后真实多段文本传给模拟分镜，不把摘要当原文。单章过大切分完整覆盖。
5. 确定性故障／恢复：不同主题进度独立；版次/规则/模型变更失效；坏缓存、伪造来源、重复、无进展不跳块；同主题并发共享；单个取消不影响其余等待者；全部取消后保存已完成工作，不派发下一块；重启续读；写盘失败不宣称成功。
6. 在用户同一个in-app浏览器http://localhost:3000/验证选题、字数/等待文案、换批和前批回看。可用独立端口稳定HTTP服务作为真实API证据，但必须明确与页面会话差异。不得生成分镜、图片或声音。

验收：仅“至多5篇推荐”的可用性，不宣称全书穷举或语义零遗漏。无法读取原文的范围拒绝，不拼造原字。其他聊天造成的界面重载不等同选题失败，应区分网络中断与生成结果。
