# 全书索引与主题故事缓存：可执行流程

1. 使用独立空运行目录与当前配置的真实提供方，请求《警世通言》/给我一个反转。保存流事件、耗时与返回的来源。预期：首次索引字数从 0 增长到全文，随后选题；最后返回至多五篇已核对故事。
2. 在同一运行目录重复同书同主题。预期：直接复用主题故事缓存，返回相同未排除候选，不再发出正文或选题模型调用；记录耗时和缓存提示。
3. 将排除标题设为第一批故事标题，换一批。预期：只在缓存故事或索引中选择其他来源，不重读原文，不出现已排除标题或同一来源改名。
4. 更换主题。预期：读取合并全书索引后仅按新主题筛选，不再次发送原文。
5. 重启提供服务的 Node 进程，重复第 2 步。预期：磁盘缓存仍可直接使用。
6. 自动化补充：版本/正文/规则/模型变化不命中旧缓存；损坏缓存不泄漏无效来源；相同任务并发共享；一个等待者取消不影响其他人；无人等待后不派发后续批次且保留已完成批次；存储错误安全返回且无虚假成功；超大索引按≤30,000字符候选分组并递归合并，尾部候选仍能入选。

真实步骤只用于选题，不开启分镜、图片或声音生成。优先通过同一应用接口验证；开发预览重载时用稳定的独立服务验证，并明确环境差异。
