# Desktop overview E2E

Use Node 24.22.1/pnpm 11.25.0, pnpm desktop:preview, a disposable generated-record library and readonly provider. Prefer/reuse the in-app browser; if tool access is disabled use the user-permitted separate Playwright fallback and disclose it. Do not change personal data, call paid generation, prepare resources or package the native app.

1. Start the reader development service for the disposable library, then desktop Vite preview with the same SHIQU_DATA_DIR and optional VITE_DESKTOP_READER_URL. Expect exactly 概览 / 生成队列 / 设置, overview selected, no iframe or embed toolbar, and no permanent preview notice. With URL configured, main preview action opens the actual reader in a separate browser tab; without it, show actionable preview setup text and no native service action. Invalid/credentialed/external/root-with-query URL must not be launched.
2. Seed synthetic generated records covering completed, active, failed, pending choice and paused/idle, with saved flags. Compare displayed summary counts and recent/actionable records against real /__desktop/library data. These are generated-record counts, not all published/demo stories. View should not modify SQLite or enqueue work. Loading shows dashes; forced summary failure shows error/retry and must not claim an empty library. Empty-library preview has an inviting start/open action and honest zero counts after a successful read.
3. Verify native shell with mocked IPC separately from packaged runtime: initial unconfigured setup opens settings; configured readonly starts on overview. For stopped service, primary action calls save_settings when dirty, detect_node, start_server, then open_reader. Running service skips start. Save/runtime/start failure never opens; opener failure leaves running status and allows another open. During pending operations repeated actions are disabled. Retain stop and settings-lock behavior.
4. Navigate queue/settings and back using pointer and arrow/Home/End keyboard actions. Queue still reads the same summaries and preserves existing rendering. Saved provider/model/path and Node readiness are labelled accurately; no key material or invented provider connection success is shown. Phone panel preserves LAN and private internet URL/QR selection/copy behavior and notices. Preview does not gain native service/credential access.
5. Inspect actual screenshots at 760×640, 1040×820, wide/tall and narrow stacked sizes. Primary action, metrics, actionable work and recent records have clear hierarchy, no overlap or horizontal overflow; all lower content and sharing controls remain reachable by scrolling. Capture empty/populated and running/stopped states.
6. Run focused overview/launch tests and full applicable regression checks. Browser checks and native-IPC simulation are not native runtime smoke; explicitly record unrun platform/browser-launch and prepared-bundle tests. Verify obsolete embed files and iframe-only CSP grant are removed and capabilities remain local-only.
