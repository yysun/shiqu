# Desktop reader tab E2E

Use Node 24.22.1/pnpm 11.25.0, a disposable SQLite library, read-only provider, and the in-app browser. Never connect to a personal library for mutations or run paid generation.

1. Start the existing reader development server at an unused loopback port with `SHIQU_DATA_DIR` set to the fixture library and `SHIQU_AI_PROVIDER=readonly`. Start `pnpm desktop:preview` with the same directory and `VITE_DESKTOP_READER_URL` set to that reader's loopback origin. Open/reuse desktop preview tab. Expect the existing three tabs plus 阅读与创作, with service and sharing controls still visible.
2. Select 阅读与创作. Expect the real reader frontend (not a copied screen) in a titled sandboxed frame. Navigate discovery and shelf, open a fixture story, change its page/bookmark, and verify progress through reader HTTP API. API writes must succeed from the reader's origin. Verify the frame cannot access the parent's DOM; native permission denial is evidenced separately by pinned Tauri ACL implementation and unchanged capabilities (bridge globals may still exist in Windows subframes). Open reading preferences and export/download a ZIP using same-origin fixture media.
3. Switch to queue/settings/shelf and back. Expect the same frame document/current story and state. Use desktop reload; expect a new frame document and saved progress restored from the shared server.
4. Use keyboard arrow/Home/End navigation across all tabs and inspect selected tab/panel association. At the native minimum 760px width and at 1040px verify reader viewport and service controls remain usable; check a narrow stacked layout.
5. Without a preview URL, expect actionable setup instructions and no iframe. With invalid/external/same-origin URL, expect refusal and no iframe. Simulate unavailable reader navigation by refusing its network request, expect persistent reload/service guidance, then restore networking and reload to recover. Existing server lifecycle integration tests separately cover real stop/restart and progress persistence.
6. Regression checks cover running/stopped status rendering (no frame when stopped), allowed/rejected URLs, CSP and unchanged native capability scope, plus existing server access/lifecycle tests. Native packaged start/stop/IPC/download behavior is not executed without explicit preparation/build authorization; report this limit instead of claiming native runtime verification.
