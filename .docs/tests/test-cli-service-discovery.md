# CLI 服务发现与按需启动

全程使用隔离书库与只读提供方或受控生成适配器。

1. 空闲书库上同步发出两条真实 `stories list`。两条 JSON 回执都成功，只由一个实例持锁并应答，服务自动退场。随后新的 CLI 操作仍可启动。
2. 启动普通浏览器和桌面 JS 服务。经真实 CLI 读取同一本书库、改名，并从当前浏览器 API 查到新名字，无第二个书库持锁者。受控在线服务全程接收选题、准备、确认、审片、修订、继续和完成，保存步骤的模型调用为零。
3. 保留旧服务记录，让不同服务占用旧端口。验证新请求不抵达旧地址的操作端点，死实例可恢复，仍持锁的旧版服务明确报占用。验证跨站或无身份调用无法访问本机命令端点。
4. 受控自动服务和已有浏览器服务分别显式执行 `run --until reviewed`。保存审片通过的故事，绘图计数为零。并发观察其他故事仍可派发；在同一服务上通过显式继续完成该故事。对于已有付费绘图在途的目标，有限运行立即报告冲突，同服务第二个目标不受影响。有限运行仍在进行时第二条全量运行报冲突。同一个 `reviewed` 回执重复读取仍保持绘图限制。浏览器重放已处理的恢复操作不会解除，新授权恢复后可以绘图。普通查询、读配置、预览和导出没有隐式模型调用。
5. 生命周期回归。挂起在启动和运行的请求均有上限，取消命令只取消对应请求，最后一个请求退出后释放锁。启动失败和快照路径保持已有错误处理。

6. 使用两个调用目录分别提交 stdin 和相对路径文件。验证第二条使用它的调用路径和环境，且用户环境值没有出现在服务记录或请求。紧接前一查询运行 `backup` 和 `--backup`，只能看到已完成数据，备份中无服务记录。
7. 从桌面 bundle 的 Node 入口和 npm bundle 入口验证自动启动，使用隔离目录，在两种环境里均不依赖系统 npm 或公开网络。自动服务只监听回环，旧的无服务命令保持可用。

8. 让在线审片在受控生成器中失败，经 CLI 按故障编号授权重试。重试保存后无新的调用，显式 run 推进。让一次保存成功之后的状态投影失败，从数据库确认版本和回执存在，服务没有自行派发。无效令牌保存及旧请求重放不改变较新运行范围。

9. 达到审片后，停止空闲服务并用同版本重新打开原书库。等待超过调度周期，零绘图。显式继续才绘图。自动服务空闲退出后同样恢复等待。
10. 控制源库及目标库都在线。复制已完成作品并核对内容和原图，源库写入计数为零。空闲服务创建 CLI 与桌面备份并校验、恢复到新目录。夹住真实生成或索引流任务，经实际桌面 stdin 先收到关联编号的拒绝，再重试得到接受。常规停服和两个备份入口均返回占用；原服务地址仍可访问，备份路径不存在。结果收尾后重试成功。

11. 在已排队的绘图前让无效 CLI 停点的查询等待，调度周期也不得发图。真实在途图返回冲突，过期的旧租约允许读取审片停点。浏览器授权已落盘但投影失败时，调度仍认本次授权；重放旧编号不改变新的等待意图。CLI 拒绝符号链接书库并可从已消失或 PID 被复用的服务记录恢复。

12. 用隔离 preloader 卡住启动进程，经真实 CLI 发送 SIGINT。CLI 退出码为 130，输出中断回执，书库没有遗留拥有者。冷启动并发用例另证已有可用服务继续接收命令。
