## 改前结论

整体布局可保留。窄屏和桌面都通过分隔线、左对齐的画风名与行内靠右的操作区，让用户看出哪项操作属于哪套图。加粗的画风名在最左边，状态与幅数相邻且只在套图行里出现。建议先将创建时间留给同画风的多个版本，再去掉可见的「横图套图（2 套）」标题。

复查对象是《画壁》的「故事设置」。主要任务是认出已有横图版本，找到对应的暂停或删除操作。样本中极简线描显示生成中，白描连环画显示已完成。桌面与窄屏截图来自本地开发环境。

## 改前优先建议

### 轻微 · 每套都显示完整创建时间，拉开了画风与操作

当前两套画风各异，样本里用画风和状态即可区分。两串含年份和秒数的时间各独占一行，在 390 × 844 下各占 23 CSS px，右侧操作的上边缘比画风低约 50 CSS px。在 320 × 520 下，套图行有效宽度为 214 CSS px，两者相距约 61 CSS px。界面实现取的是套图创建时间，现有流程测试覆盖按默认画风制作第二套后两套都保留的场景。 [390 × 844 原图](mobile-390-active.jpg) · [320 × 520 原图](mobile-320-active.jpg) · [测量](measurements.json) · [时间取值](../../../../../../../client/ui/StoryLandscapeStep.tsx#L19) · [流程样本](../../../../../../../tests/production-reader-exit-flows.test.mjs#L660)

建议画风唯一时省去可见时间。同一画风有多套时用常规字重显示短创建时间，例如「11/27 22:34」，精度以能区分这些套图为准。需要按日期回找不同画风的人也可能依赖时间，若该任务常见，所有套图均可显示低强调的短时间。

### 轻微 · 套数标题占据一整行

「横版插图（可选）」和「横图套图（2 套）」左边对齐且紧邻，两个标题之间没有新内容。在 390 × 844 下，第二行占 20 CSS px，随后还有 4 CSS px 间距。套图本身已有可扫描的画风名，第二个标题和计数在当前任务里价值低。按 Playbook 的简洁与层级原则，建议去掉可见的第二个标题，直接列出套图。若以后有部分隐藏的套图或独立计数任务，再评估计数入口。 [窄屏原图](mobile-390-active.jpg) · [测量](measurements.json)

验收可用两组样本。不同画风时，读者一眼找到对应套图及操作。同一画风且进度相同时，读者能靠时间指出指定版本。320 CSS px 宽时允许操作整组靠右换行，并检查分隔线和右对齐仍能明确显示操作归属。

## 改前分项检查

以《The UI/UX Playbook》原文、接近性示意图及技能目录为依据。结果限于生成中和已完成同时可见、以及已完成套图删除确认这两个采样状态。

| 部位 | 规则 | 观察与结果 |
| --- | --- | --- |
| 横版插图步骤与套图标题 | 简洁、标题层级 | 待改善。两级名称相近且相邻，独立计数在当前清单没有决策作用。 |
| 套图分隔与靠右操作 | 对齐、接近性 | 通过。画风有稳定的左边缘，分隔线位于上一条操作之后，暂停、删除均在各自套图组内。 |
| 画风、状态与幅数 | 字重与层级、以文字给出状态 | 通过。画风为 600 字重，状态与幅数为 400，生成中的套图进度以文字显示一次。 |
| 横图卡片文本 | 文本对比 | 通过。生成中背景上，按浏览器计算色值换算，画风、进度与普通操作的对比分别为 7.04:1、4.92:1、4.95:1。 |
| 创建时间 | 依任务取舍信息、相关项放在一起 | 待改善。完整时间各独占一行，日期的版本识别价值取决于套图是否容易混淆。 |
| 删除确认 | 危险操作层级、就地反馈 | 通过。390 × 844 下，提示和确认出现在白描套图内，其他套图保留原操作。点取消后恢复原入口。 |
| 手机与桌面适配 | 响应式布局、对齐 | 通过。390 × 844、320 × 520 和桌面侧栏都能看到这两条样本的画风及动作归属。 |
