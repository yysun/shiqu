## 修复前的审核记录

## 范围与依据

审核对象为拾趣书架的「作品与导出」及结语页共用的导出列表。目标是让准备打印的读者找到两种打印格式，在缺图时原地制作，再完成下载。证据来自 2026-11-27 的工作区版本（基于 `4e1d1af2`）和 ChatGPT 应用内浏览器。浏览器视口与 JPG 像素尺寸相同，测量来自 DOM 的 CSS 像素。使用四幅画的隔离书库和受控绘图结果，包含一次故意失败。原始用户截图为《狸猫换太子》37 幅的缺图状态，视口与缩放未知。它能说明旧版的问题，无法用于等比例测量。

设计规则参照 UXPeak 的《UI/UX Playbook》，核对了操作优先级、邻近性、留白和信息顺序的原书图例。其余适用检查采用技能的规则目录。焦点与尺寸另用实际键盘操作和 DOM 测量核对。 [规则目录](</Users/esun/Documents/Projects/ui-checker/audit-ui-design/references/ui-design-rules.md>)

## 按影响排序的发现

### 重要 · 320 × 568 上，点完打印仍看不到制作入口

Letter 双面 PDF 可以在首屏点击。缺图反馈出现后，状态块只露出上半部分。面板滚动位置为 0，制作链接底边在视口 y = 624.8，低于视口底边 56.8 CSS px。滚动后可达，横向无溢出。把最有用的解决动作放在触发结果的可见区域，是这一步的优先级。受影响范围为测得的小屏缺图状态，高置信；真实用户发生率未知。 [首屏](compact-missing-top.jpg) · [滚动后](compact-missing-scrolled.jpg)

保留右对齐的文字链接。把「缺 4 幅横图」与「开始制作横图」放在状态块首行，短屏触发缺图时把状态块滚入可见区。复测 320 × 568，从首次选择任一打印格式开始，确保无额外滚动操作即可看到缺图数量和完整链接，并保留键盘和退出路径。

### 次要 · 缺图块的状态和下一步相隔过远

390 × 844 时，缺图块高约 139 px。先出现「横版插图 / 未生成」，再出现用途说明和「打印所需横图已就绪 0 / 4 幅」，12 px 的制作链接单独右对齐，与底部署名链接近似。两条 14 px 粗体打印格式在缺图、制作中和完成时都保持同样的可点击表现。现有制作链接的 44 px 高触控区够用，问题在于原因和动作的分组及相对强调。桌面待重试状态也在错误信息和重试链接之间留出较大空白。高置信；读者是否因此反复尝试打印尚无用户证据。 [手机缺图](mobile-missing.jpg) · [桌面缺图](desktop-missing.jpg) · [桌面重试](desktop-retry.jpg)

合并「未生成」与数量信息，将长用途说明移出首次恢复的阅读顺序。收到缺图结果后，在「打印」组增加一处共享的状态提示，让两条格式都能读出同一个前置条件。复测 390 × 844 和 1200 × 800，状态块首行能同时读到缺图数量和下一步，绘制中仍清楚显示当前进度，失败信息和重试仍在同一个块里。

### 次要 · 结语页的焦点框看起来像打印格式分隔线

手机结语页对「横版 PDF」按 Tab 再按 Shift+Tab，可聚焦到该按钮。实测为 2 px 实线、外偏移 3 px，父列表为 `overflow: hidden`。截图只在该行底部明显看到浅线，左、右和顶部被父级裁掉。受影响范围为已复测的深色首行，高置信。 [键盘焦点](mobile-ending-focus.jpg) · [同一列表的常态](mobile-ending.jpg)

为结语页的导出行使用内收焦点框或其他完整的行内焦点样式。依次 Tab 到两个列表的首行、中间行和末行，确认每一行都有完整可辨的焦点范围。

## 走查结果

- **缺图打印。** 从书架打开缺图样本，选择 Letter 双面 PDF，原地启动横图。观察到 3 / 4 幅、仅第 2 幅待重试。重试后再次选择 Letter 双面 PDF，确认第 2 幅作封面，通过未署名确认并下载 PDF。文件可读，4 页，纸张为 612 × 792 pt（Letter）。验证止于数字文件。 [失败](desktop-retry.jpg) · [就绪](desktop-recovered.jpg) · [选封面](desktop-letter-cover.jpg)
- **已有横图。** 第二个已完成样本选择横版 PDF，直接打开横版封面选择。此次对该格式走查至选封面。
- **结语。** 确认深色导出列表保留相同顺序和用途分组。复现键盘焦点裁切。 [结语导出](mobile-ending.jpg) · [焦点](mobile-ending-focus.jpg)
