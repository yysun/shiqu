# CHANGES-C001 · 断网后仍显示已是最新版本

- 候选 `676a5335`，macOS arm64 原生控制台，显示已安装版本 0.18.0，本机故事服务停止。
- 维护者报告断网后点「检查更新」，页脚显示「当前版本 0.18.0　检查更新　已是最新版本。」。Codex 随后在原生控制台读到了同一页脚文案。维护者点击时的网络连通性没有另行采样。
- 预期保留本机版本号，并提示「暂时无法检查更新，请稍后重试。」。实际文案把一次未能证明已联网检查的结果显示为已是最新。P1，影响手动更新检查结果的可信度。
- [GitHub 发行版接口](https://api.github.com/repos/yysun/shiqu/releases/latest) 于 22:32 UTC 返回 HTTP 200，响应头为 `Cache-Control: public, max-age=60, s-maxage=60`。候选的 `newerDesktopRelease` 使用默认 HTTP 缓存策略。[Fetch 标准的缓存行为](https://fetch.spec.whatwg.org/#concept-request-cache-mode)
- 隔离 Chromium 复现使用同一提交的版本检查函数与请求参数，将目标 URL 指向临时 loopback 接口。接口成功返回一次稳定版 0.17.0 和相同的缓存时长，随即断开后续请求。再次检查仍返回表示「已是最新」的结果，服务端请求数保持 1。控制组只把缓存策略设为 `no-store`，断开时发起新请求并产生网络错误，恢复接口后重新返回「已是最新」。
- 先前断网旁证强制中断每一个请求，未预热缓存。原生运行和受控复现都记录于此。对照实验验证缓存能造成这一现象；维护者那一次点击在 WebView 内部的缓存命中没有直接遥测。
